# Confluo

The project is owned by Orbit Labs: `https://github.com/Orbit-Labs-AI/Confluo` (formerly Paper Crawler). The local runtime directory is `.confluo/`, selected through `CONFLUO_HOME` (the legacy name was `.paper-crawler/` / `PAPER_CRAWLER_HOME`).

`AGENTS.md` is the shared instruction source. Everything older lives in two archives; read them with `git show <ref>:<path>` or a separate worktree, and treat them as reference material, not as the current system:

- tag `v2-drafts`: the full v2 design-stage drafts (the design brief, long designs 00–09 with DDL, algorithms, task cards and acceptance criteria, the ADR full text, the survey with raw data, the design process record and session logs 011–013);

Read `README.md`, `docs/INDEX.md`, `docs/plan/progress.md` and `docs/plan/v2/README.md` first; `docs/archive.md` explains both archives.

## Acquisition and local-state constraints

- Acquire papers through legitimate sources and authorized user credentials, following robots.txt/ToS and conservative source-specific rates with an identifying user agent. Exclude paywall/CAPTCHA bypasses, impersonation, pirate sources and redistribution features.
- v2 is a multi-user platform. Auth-gated full text is retrieved on the user side with that user's own credentials, only on explicit request, and stays private to that user. Shared data holds only public metadata and content whose license permits redistribution, and anything derived from private content stays private. The compliance hard constraints HC-01 onward in `docs/plan/v2/08-compliance-security-privacy.md` are binding.
- Keep credentials, cookies, sessions and downloaded PDFs in ignored local storage. Local runtime config/state lives in ignored `.confluo/`, selected through `CONFLUO_HOME`.
- Protect both runtime homes with `-e .confluo -e .paper-crawler` whenever an authorized cleanup uses `git clean -x`; existing checkouts may still hold credentials and databases in the legacy `.paper-crawler/`, and this preserves them even when Git ignore rules are bypassed.

## Scout (local AI-venue search service)

`scout/` holds Confluo Scout, a single-user local service (D-077 draft; design in `docs/plan/scout/`): `scout/server/` (Python 3.13, uv, package `confluo_scout`), `scout/web/` (React 19 + Vite + TypeScript, pnpm), `scout/registry/venues.yaml` (venue list), `scout/compose.yaml` and `scout/Dockerfile` (services `scout` and `qdrant`). Its data lives in `$CONFLUO_HOME/scout/`; the live SQLite database and Qdrant's storage are the Docker volumes `confluo-scout_scout-db` and `confluo-scout_qdrant-storage`, with consistent copies (database backups, Qdrant snapshots) in the data directory. Commands run from `scout/`: `make up`, `make down`, `make logs`, `make check` (ruff, pytest, web typecheck and build), `make backup`, `make embed-serve` (optional host GPU accelerator). Do not open the live database from the host, even read-only: on 2026-11-19 a host `sqlite3` session through the virtiofs mount corrupted it. Inspect data through the web UI, the API or a copy of a backup. Scout does not establish the v2 layout of milestone V0.
