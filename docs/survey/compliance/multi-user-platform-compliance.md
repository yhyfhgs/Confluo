## 0. 结论速览

1. **角色变了，许可前提跟着失效**。v1 的合规基础是"用户本人、个人科研用途、本地存储"。v2 成为平台后，平台是**运营者和被许可方**，而许多条款的授权对象或用途前提是"被许可人本人或其机构授权用户""非商业""不得代第三方使用"。具体来说：IEEE API 只允许在被许可机构内部做非商业用途，不得代第三方使用 [C58]；S2 的 API key 只能交给被许可方自己的授权人员 [C9]；ORCID 公共 API 限非商业，凭证归个人所有 [C31]；Elsevier API 与 AI 系统结合时，只允许在"为授权用户个人服务的封闭托管环境"中使用 [C52]。
2. **元数据可以做成共享底座，摘要要分级处理**。书目事实可视为 CC0 或事实数据，包括 Crossref、OpenAlex、DBLP、OpenCitations 和 ORCID 公共数据文件 [C1][C3][C29][C33][C32]。**arXiv 的描述性元数据（明确包括摘要）采用 CC0** [C14]，这是由自身许可条款明确以 CC0 发布摘要、可无条件再发布的最大摘要来源（许可说明规定 CC0 适用于全部元数据 [C15]，API 条款写明元数据包括摘要 [C14]）。（核验补充）DOAJ 对文章级元数据（含摘要）同样声明 CC0 弃权，但注明该弃权不影响所描述作品本身的版权；DOAJ 只收录 OA 期刊，其摘要可按文章许可（多为 CC 系）展示，是 OA 期刊范围内的第二来源 [C98]。其他来源各有限制：Crossref 声明摘要版权归出版方或作者 [C1]；NLM 不主张摘要版权，但提醒出版方可能主张 [C19][C20]；OpenAlex"出于法律原因"不提供明文摘要 [C4]；S2 API 可能"出于法律原因"不返回摘要 [C11]；Springer Nature 的 API 条款把摘要按全文同等限制，只许个人使用 [C39]；I4OA 明确表示第三方不得再发布摘要全文，除非原许可允许 [C37]。
3. **全文按"逐篇许可"决定能否共享**。只有许可允许再分发的 OA 全文（CC BY、CC BY-SA、CC0；NC 许可取决于平台是否商业化）可以进入共享层。以下都不行：arXiv 默认许可的论文，平台不得存储并对外提供 [C14]；bioRxiv 要求链接回源、不得再托管 [C26]；PMC 禁止从主站系统下载 [C22]；OpenAlex 提供的 PDF 保留原版权 [C5]。
4. **auth-gated 全文必须"每用户自有凭证 + 私有存储 + 不共享"**，这是多数条款的共同要求，不是本项目的偏好。各家条款的要求如下：
   - key 和语料都属个人，不得共享给第三方，包括机构知识库和社交协作网络；超出范围的内容只能以不超过 200 字符的片段加 DOI 链接的形式外发 [C51]；
   - 内容只能存放在无第三方访问的内部服务器，且仅在 TDM 项目期间存放 [C55][C39]；
   - 与 AI 系统结合时，不得把内容（含生成的回答）系统性存储或再分发给其他授权用户 [C52]；
   - 机构许可只覆盖"授权用户"，并禁止系统性下载 [C60][C71]；图书馆政策禁止共享口令，禁止用机器人或"intelligent agents"系统性下载 [C72]。

   另外，EZproxy 默认安全规则会把"24 小时内超过 4 个国家""60 分钟内 IP 变化超过 20 次"判定为账号共享或账号被盗并封禁 [C73]。因此**执行位置最好放在用户自己的设备或浏览器**，平台服务器不代持机构凭证，也不从平台出口代用户访问出版商。
5. **LLM 生成的 TL;DR 是新增的高风险面**：
   - USCO 第 3 部分报告认为，以概括或删节原作为目的的 RAG 更难构成转换性使用 [C43]；
   - Advance Local 诉 Cohere 案中，法院在驳回动议阶段（2025-11-13）认定"替代性摘要"可以支撑直接侵权主张；这是诉答阶段的认定，不是实体判决 [C44]；
   - IEEE 禁止把 API 内容用于任何 AI、ML 或 LLM 派生用途 [C58]；Elsevier 把 RAG 和向量库都算作"AI System"并加以限制 [C52]；
   - Cloudflare Content Signals 的 `ai-input` 信号明确覆盖 RAG 和 grounding [C47]；
   - 中国对 AI 生成文本要求显式标识加隐式标识 [C85][C84]；EU AI Act 第 50 条自 2026-08-02 起适用 [C92]。
6. **对上游的礼貌性要按平台整体计算**。各源的限速口径如下：arXiv 的限速按"你控制的所有机器合计"计，每 3 秒 1 次、单连接 [C14]；NCBI 的 key 限速不论 IP 合并计算 [C21]；Crossref 的限额按"个体用户"计 [C2]；OpenAlex 按 key 计费 [C3][C8]。因此 v2 必须做到：每个上游只用一个平台身份，全局统一调度，优先用快照，建立共享元数据缓存；**禁止用多 key 或多 IP 规避限速**。
7. **中国大陆上线门槛高**：
   - 只要有评论、点赞或信息分享功能，就大概率属于"具有舆论属性或者社会动员能力"，上线前要做安全评估 [C77]，并在上线后 10 个工作日内做算法备案 [C76]；
   - 跟帖评论服务在定义上**包括点赞**，要求后台实名、审核巡查、信用分级 [C81]；
   - 个性化推荐必须公示基本原理，提供"不针对个人特征"的选项或关闭开关，并允许用户删除标签 [C76]，这与 PIPL 第 24 条的要求一致 [C78]；
   - 调用已备案大模型的 LLM 功能，需要到地方网信部门登记，并公示模型名称和备案号 [C87]。
8. **欧盟**：
   - DSA 的通知处理（第 16 条）和理由说明（第 17 条）适用于所有托管服务；
   - 推荐透明（第 27 条）属于第三节，**小微企业可豁免**（第 19 条）；
   - 非画像推荐选项（第 38 条）只约束月活不低于 4500 万的超大平台 [C90]。

   中国规定第 17 条和 PIPL 第 24 条已经强制要求同类能力，所以建议**全局统一实现**，不按法域分叉。
9. **美国**：
   - COPPA 只针对面向 13 岁以下儿童的服务，或实际知悉在收集儿童信息的运营者 [C93]，设定最低年龄并做年龄声明即可保持不适用；
   - §230 明确不影响知识产权法 [C95]，版权通知需要走 DMCA §512 指定代理人机制（费用 $6，3 年续期）[C96]；
   - 平台自己用 LLM 生成的内容属于平台自有内容，**不能指望 §230 豁免**（⚠ 推断，见 LQ-14）。
10. **UGC 先例**：ResearchGate 因托管用户上传的出版商 PDF 被 Elsevier 和 ACS 起诉，慕尼黑地区法院 2022-01 认定平台要对侵权内容负责，双方 2023-09-15 和解，和解后上传时需做权利检查 [C75]。因此 v2 **不提供公共全文上传或转存功能**。

### 1.2 方法与证据分级

1. **一手优先**。条款、政策、法律原文尽量直读官方页面，记录页面上标注的"最后更新"日期。法条只摘要点，不整段引用。
2. **被挑战门拦截的页面不绕过**。遇到 Cloudflare、WAF 或 403 一律停止，改用检索摘要或二手来源，并标 ◐。这条纪律与 v1 的 D-014/D-020 一致。
3. **交叉核验**。同一事实尽量找到两个来源，比如 Wiley 的限速同时查了 Wiley 页面（403）、WileyLabs 官方仓库 README 和 HKUST 图书馆指南。
4. **推断显式标注**。凡是从条款推出的工程结论，一律写"推断"或列入 LQ，不当作条款原意。

### 1.4 与既有文档的关系

- **v1 红线继续有效，并需要扩展**：
  - 00-requirements §5 第 1–5 条：不绕付费墙、不对抗风控、不再分发、不做全网采集、Google Scholar 不作自动化主源；
  - AC-0.1–0.5；
  - D-006：人在回路登录；D-014：诚实 UA，遵守 robots 与 Content-Signal；D-020/D-024：ACM 出列。

  00-requirements §5 第 6 条把"多用户"列为非目标，v2 需要用新 ADR 显式修订这一条，但要**保留第 3 条（不再分发）的实质内容**。这与 [startups-and-products](../market/startups-and-products.md) I-12 的结论一致。
- [aggregators-repositories](../sources/aggregators-repositories.md) §2.3.4 已把许可分为三档，§4 Q2/Q3 已列出"摘要展示"和"商业化"两个问题。本文在此基础上补充逐条条款出处，⚡ 并修正其中两处口径：
  - "S2 数据集 ODC-BY 可用于展示摘要"需要附加一个限定：ODC-BY 只许可数据库权，不覆盖各条内容本身的版权 [C13]；
  - CORE"可商用"需要附加一个限定：推荐、检索、发现类产品必须联系 CORE 取得许可 [C34]。

**关键判读**：

1. **"CC0 数据库"不等于"其中每一段文本都是 CC0"**。数据库发布方只能放弃自己拥有的权利。ORCID 在公共数据文件政策中直接写明了这一点（不覆盖记录中链接的论文，个人的隐私权和公开权仍然存在）[C32]；ODC-BY 第 2.4 条也声明不覆盖各条内容本身的权利 [C13]。OpenAlex 不提供明文摘要就是同一逻辑的体现 [C4]。因此 v2 的权利判断必须做到**字段级**，不能停在来源级。
2. **arXiv 摘要是由自身许可条款明确以 CC0 发布、可无条件展示的最大摘要来源** [C14][C15]。它对 CS/AI、物理、数学、数量经济等领域覆盖好，卡片应**优先使用 arXiv 版摘要**；已发表论文的期刊版摘要反而受限。（核验补充）OA 期刊论文可以用 DOAJ 文章元数据中的摘要作为第二来源，但 DOAJ 的 CC0 弃权不覆盖作品本身，展示时仍须按文章许可署名 [C98]。
3. **会触发"商业化开关"的来源**：ORCID 公共 API 禁止创收用途 [C31]；CORE 要求可能变现或属于推荐、检索类的产品先取得许可 [C34]；T&F、Elsevier、Wiley、SN 的 TDM 均限非商业（§2.3）；CC BY-NC 内容也受影响。S2 协议没有一般性的非商用条款，但禁止"出售、分发 API"[C9]，收费平台展示 S2 数据是否构成出售，见 LQ-08。
4. **须声明来源的义务**：NLM 要求注明"Courtesy of the U.S. National Library of Medicine"并保持数据最新 [C18]；S2 要求署名"Semantic Scholar"[C9]；EBI 和 CORE 期望或要求署名 [C24][C34]。这些要求应作为 provenance 字段进入数据模型，由展示层自动渲染。

**加入 I4OA 的出版商**：I4OA 公布的出版商名单（`data/publ.txt`）截至 2026-09-26 共 112 家 [C38] [LIVE]。按字符串匹配，**在名单内**的有 ACM、Cambridge University Press、Emerald、Frontiers、IOP Publishing、MDPI、Oxford University Press、PLOS、SAGE、The Royal Society、Walter de Gruyter、Wiley；**不在名单内**的有 Elsevier、Springer Nature、Taylor & Francis、IEEE、ACS。I4OA 页面同时说明，经 Crossref、PubMed 等公开的摘要**仍受版权保护**，只有摘要原许可允许时第三方才能再发布；页面并没有为成员摘要提供 CC0 之类的开放许可（核验修正：原文未出现"不等于 CC0"的字样，此处改为页面原意）[C37]。因此加入 I4OA 只能说明"更可能在 Crossref 中有摘要"，不能作为"可以在卡片上展示全文摘要"的依据。

#### 2.2.3 TL;DR：S2 TLDR 与平台 LLM 摘要

**S2 TLDR**：由 SciTLDR 模型生成，数据集许可为 ODC-BY；README 要求在产品或服务中使用时引用 TLDR 论文 [C12]。通过 API 展示时须署名"Semantic Scholar"[C9]。风险低，但它依赖 S2 的 key 和限额 [C10]。

**平台自己生成的 LLM 摘要**：风险大小取决于**输入**的权利状态，另外叠加**输出**端的义务。

| 输入 | 风险 | 主要依据 | 处理 |
|---|---|---|---|
| arXiv 摘要（CC0）、CC BY 或 CC0 的摘要和全文 | 低 | CC0 与 CC BY 均允许改编；CC BY 须署名并注明修改 [C14][C41] | 可生成并跨用户共享；须标注"AI 生成，基于某作品（许可）"并给出原文链接 |
| CC BY-ND、CC BY-NC-ND 的内容 | 中 | 摘要可能构成演绎材料 [C42] | 默认不生成共享 TL;DR；是否可行见 LQ-04 |
| 受版权保护、经 Crossref 或 PubMed 分发的摘要 | 中 | USCO 第 3 部分报告：以概括或删节原作为目的的 RAG 更难构成转换性使用 [C43]；Cohere 案中"替代性摘要"被认定可以支撑直接侵权主张（2025-11-13 驳回动议阶段的认定，非实体判决），同时因幻觉内容冠以出版商商标，被告还面临商标主张 [C44]；Ross 案中，地区法院认定用 headnote（一种短摘要）训练竞争性检索工具不构成合理使用，第三巡回法院 2026-06-11 已听审，截至检索日未见判决 ◐ [C45]；中国广州互联网法院的奥特曼案中，生成式 AI 服务商被判侵犯复制权和改编权，法院要求服务商建立投诉机制、作风险提示、做显著标识 [C46] | 共享层只允许**短小、事实性、不复述原句**的 TL;DR（长度上限和相似度阈值见 LQ-05），并且永不替代原摘要；是否可行由法务定（LQ-05） |
| 出版商 API 取得的内容（IEEE、Elsevier、SN API） | 高或禁止 | IEEE 明确禁止把内容用于训练、改进 AI，以及"为 AI、ML、LLM 使用而创作演绎作品"，也禁止为 AI 使用而做数据挖掘 [C58]；Elsevier 规定与 AI 系统（明确包括 RAG、MCP、向量库、缓存层）结合时，只能在为授权用户个人服务的封闭环境中使用，不得把内容或**生成的回答**再分发给其他用户，不得形成竞争或替代性服务 [C52]；SN 只许个人使用 [C39] | **不进入共享层**；即使在私域生成，也要先经 LQ-06 确认 |
| 用户私域中的 auth-gated 全文 | 私域内中低；共享则禁止 | Elsevier AI 条款同上 [C52]；CUP 的非商业 TDM 许可"不授权"把订阅内容上传到公共或第三方 AI 服务 ◐ [C54] | 只为该用户本人生成，结果只存该用户私域；调用的 LLM 端点须满足"封闭托管、不训练"（LQ-06） |
| 网页中带 `Content-Signal: ai-input=no`、TDMRep 保留，或 robots 具名禁止 AI UA 的内容 | 禁止 | Content Signals 把 `ai-input` 定义为把内容输入 AI 模型（RAG、grounding 等），并声明其限制构成 DSM 第 4 条意义上的明示保留 [C47]；TDMRep 是针对 DSM 第 4 条的机器可读保留协议（W3C CG 最终报告，2024-05-10）◐ [C48]；IETF aipref 截至检索仍是草案 ◐ [C49] | 输入前检查信号；有保留的一律不送入 LLM |

**推断**：平台如果成为"TDM 执行方"或"内容汇聚方"，几乎一定越出这些条款。平台最多能做的是：让用户用**自己的**权限、在**自己的**私域里做取回与处理，平台只提供软件，不接触他人的内容。

#### 2.3.3 为什么必须"每用户自有凭证 + 私有存储 + 不共享"：证据链

| # | 条款要求 | 若平台跨用户共享会违反什么 | 依据 |
|---|---|---|---|
| E1 | Elsevier：key 与语料属个人，不得共享给第三方，包括机构知识库和社交协作网络；只能分享 DOI 清单，由有权限的人自行重建 | 把 A 用户取回的全文或索引给 B 用户用，即使 B 也有订阅 | [C51] |
| E2 | Elsevier：不得使用他人凭证或共享凭证；与 AI 结合时只能在为个人服务的封闭环境中使用，不得把生成的回答再分发给其他授权用户 | 平台池化 key；把 A 的私域 TL;DR 展示给 B | [C52] |

| E4 | IEEE：不得代第三方使用 API；key 须保密；内容只能在机构内部使用 | 平台级 key 服务所有用户 | [C58] |
| E5 | arXiv：不得使用他人凭证访问 API；不得存储并对外提供 e-print | 平台转存 arXiv PDF 给所有用户 | [C14] |
| E6 | ACM–RDL 协议：只对授权用户提供；不得整体复制；发现系统性下载时可终止整个机构的协议 | 平台以个别用户的权限系统性取回 | [C60] |
| E7 | SERU：授权用户由机构界定，在馆访客离开后即失去访问权；系统性下载会被通报，**访问可能被整体暂停**（核验补充：SERU 把暂停机构访问称为"最后手段"，并提醒经代理服务器地址的合法访问也可能被误判为滥用） | 同上。且被暂停的是**整个机构**，后果外溢到非本平台用户 | [C71] |
| E8 | 图书馆政策（以 UMich 为例）：禁止共享口令；禁止用机器人、爬虫或"intelligent agents"系统性下载；禁止把版权内容发布到公开网站 | 平台代持口令，平台 agent 代用户下载 | [C72] |
| E9 | UK s.29A：TDM 复制件转给他人即构成侵权 | 跨用户共享 TDM 副本 | [C63] |
| E10 | ResearchGate 先例：平台对用户上传的侵权内容负责（慕尼黑，2022），和解后上传时须做权利检查 ◐ | 公共上传或转存全文 | [C75] |

**推论**（设计含义，不是条款原文）：

- **不得做跨用户去重**。即使两位用户取回的是同一 DOI 的同一 PDF，也不能用内容寻址等方式让 B 复用 A 的副本，否则等于 A 替 B 取回。
- **不得泄露"某人有权限"这类信号**。例如不能向 B 显示"已有人取回此文，可直接阅读"。
- **私域派生物同样只归该用户**，包括全文嵌入、TL;DR、片段索引和阅读批注的上下文。

#### 2.3.4 机构代理（EZProxy/SSO）条款对自动化与多人共享的限制

| 机制 | 事实 | 对平台的含义 | 依据 |
|---|---|---|---|
| 授权用户的定义 | SERU 的典型定义：在读学生、教职工、访问学者和合同员工等；远程访问限于授权用户；在馆访客没有远程权限 | 平台和平台员工都不是授权用户，平台只能充当用户**自己**操作的工具 | [C71] |
| 系统性下载 | 在 SERU 中属于可疑行为，出版商会通知机构，必要时暂停访问；ACM 协议写明可因此终止协议 | 平台的批量取回可能导致**整个机构被封** | [C71][C60] |
| 口令与代理 | 图书馆政策禁止共享口令，禁止"intelligent agents"系统性下载 | 服务端保存用户的 SSO 口令或会话，并由平台 agent 自动下载，属于高风险 | [C72] |
| EZproxy 风控 | OCLC 与数据库商共同制定默认规则，例如 24 小时内访问国家超过 2 个时记录、超过 4 个时封禁；60 分钟内 IP 变化超过 20 次时封禁；每小时传输超过 1 GB 时记录，（核验补充）**超过 2 GB 时封禁**。UsageLimit 可以按下载量自动暂停用户 ◐ | 服务端代理会造成"会话在数据中心 IP、用户却在别处""多个机构的会话从同一出口发出"等异常，容易被判定为共享或盗号 | [C73][C74] |
| v1 纪律 | 串行执行；1 req/6s；单平台每天 200 篇；工作时段运行；遇风控立即 BLOCKED 并冷却 | v2 在用户侧执行时照旧适用 | [I2] |

**推论**：满足上述全部约束的最简单架构是：**取回动作发生在用户自己的浏览器或本地 agent 里**（与 v1 的 Playwright 人在回路模式同构），内容存放在用户自己的设备或用户控制的加密私有存储中；平台只下发"待取清单"和元数据，不接触凭证和内容。平台也可以生成走用户所在机构链接解析器或代理的链接（如 OpenURL、WAYFless），由用户浏览器完成访问（⚠ 推断，见 DI-02 和 LQ-07）。

**调度原则**（设计建议）：

1. **上游是限速的单位，用户不是**。每个上游维护一个全局 token bucket，各用户请求按公平份额排队。
2. **请求合并与共享缓存**。同一 DOI 或查询在进行中的请求合并为一次（singleflight），并设置负缓存。Crossref 官方最佳实践第一条就是"缓存响应，避免重复请求"[C2]。
3. **快照优先**。OpenAlex 季度快照 [C100]、Crossref 年度文件、arXiv OAI/S3、PubMed baseline、DBLP 月度快照、S2 数据集作为底座，在线 API 只做增量和长尾查询（与 [I5] 一致）。
4. **诚实身份，不规避**。每个上游只用一个平台 UA 并附联系邮箱；**禁止**住宅代理、IP 轮换、多 key 叠加额度、伪装浏览器 UA（arXiv、S2、ORCID、IEEE 条款都明文禁止规避限速或伪装来源 [C14][C9][C31][C58]；核验补充：SN API 条款明文禁止"通过增加多个账号或 key 规避 API 限额"[C39]）。
5. **遵从机器可读信号**。沿用 D-014：遵守 robots.txt、Content-Signal 和 TDMRep；遇到 429、503 或 Retry-After 时退避；遇到挑战页时，该源降级到官方通道或下线。同行先例：Cool Papers 在 bioRxiv 启用 Cloudflare 反爬后主动下线了该源（见 [I7]）。

**学术场景的特有风险与先例**：

- **把全文上传到公开空间**。ResearchGate 案中，出版商先发下架通知，再在德、美两地起诉；慕尼黑地区法院（2022-01）认定平台对侵权内容负责；2023-09-15 和解后，上传时须检查 ACS 和 Elsevier 内容的权利 ◐ [C75]（另见 [I7] R75）。（核验补充）据报道，和解后的做法是上传时自动核查共享权利：权利不足的全文只能作者私存，在他人请求时私下分享，获得相应权利才公开展示。这为 LQ-15 的"个人私有上传"提供了一个行业先例。v2 **不提供公共全文上传**，评论也**不允许附带 PDF**。图片附件须声明许可，许可不明的不公开显示。
- **针对作者的指控与诽谤**。PubPeer 的匿名评论者曾被起诉诽谤，密歇根上诉法院（2016-12）认定：基于已披露事实表达的观点依法不构成诽谤，匿名身份受第一修正案保护，原告随后撤诉 ◐ [C97]。PubPeer 自 2016 年起要求评论只陈述可以公开核实的事实（见 [I7] R76）。v2 的评论规范应要求"可核实陈述"，并为作者提供回应和申诉入口。
- **AI 生成的评论**。中国标识办法第 6 条要求传播平台核验并提示 AI 生成内容，还要提供用户声明功能 [C85]。v2 评论框应有"含 AI 生成内容"声明项，平台也要做检测。
- **刷赞和操纵**。算法规定第 14 条禁止利用算法虚假点赞、评论、转发，或操纵榜单与检索结果 [C76]。反作弊能力应在公开计数上线之前完成。

### 3.2 其他设计启示（DI）

1. **DI-01 权利引擎（rights engine）应作为一级组件**。输入是来源、许可字段（JATS、OpenAlex `best_oa_location.license`、arXiv 版本许可、PMC OA 元数据）和平台的商业属性，输出是每个字段的 `rights_class` 与 `display_level_max`。展示、分享、LLM、索引等模块都只调用这个引擎，**不自行判断**。许可冲突时取更严的一方；许可缺失时按不可共享处理。
2. **DI-02 取回架构建议"用户侧 agent 加平台编排"**。平台下发"候选 DOI 与建议取回方式"清单；用户侧（浏览器扩展、桌面或本地 agent，可复用 v1 的 Playwright 人在回路登录与 `storage_state` 复用逻辑）执行取回，结果写入用户私域（本地，或用户持有密钥的 E2E 加密云存储）。平台端只看到"是否成功"这类不含内容的状态。**替代方案**是生成走机构链接解析器或代理的链接（OpenURL 或 WAYFless），由用户浏览器访问，平台完全不经手（⚠ 需结合各机构的解析器配置，LQ-07）。
3. **DI-03 "共享底座"只由开放数据构建**：OpenAlex 与 Crossref 书目数据、OpenCitations 引文、arXiv 元数据、PubMed baseline（须注明来源并保持最新）、DBLP 快照、ORCID 公共数据文件、CC 许可的 OA 全文。推荐模型的全局部分（物品表示、协同信号）**只使用共享底座和经过聚合去标识的行为数据**；个体偏好模型保留在用户维度。
4. **DI-04 卡片的默认内容组合**：题名、作者、venue、年份（V2），加 arXiv CC0 摘要（有就用）或 V3 摘录，加受控 TL;DR（标注 AI），加 CC 许可的图或排版封面，加 why-this，加开放获取与"可用你的权限阅读"标记。后一项**只在用户端计算**（HC-02）。
5. **DI-05 LLM 选型须满足合规前提**：中国区用已备案模型并完成登记；其他地区用不训练用户数据、可配置零保留的企业端点。私域内容使用私有部署或满足"closed hosted (enterprise-grade)"的端点（Elsevier 条款措辞，LQ-06）。
6. **DI-06 上游治理面板**：每个上游显示配额、成本（OpenAlex `cost_usd`）、429 与挑战计数、robots、Content-Signal 和 TDMRep 状态、条款版本哈希。条款或 robots 变化时自动告警，并把相应来源置于"待复核"状态（与 v1 canary 机制同构）。
7. **DI-07 商业化开关是架构参数，不是营销决定**。`platform.commercial=true` 会自动停用 ORCID 公共 API、未取得许可的 CORE、NC 内容共享，以及用户私域中的 Elsevier、Wiley、SN、T&F TDM 流程（除非另签商业 TDM 许可）。所以商业模式应在设计冻结前确定（LQ-03）。
8. **DI-08 社交功能分三期**：
   - 期 1：私有反馈，不构成"发表"（LQ-10）；
   - 期 2：公开的只读聚合信号，如收藏数，需要反作弊；
   - 期 3：评论，满足 HC-15 后开放，按地区依次开放。

   这与 [I7] I-13 的分期建议一致，本文补充了法规依据。
9. **DI-09 数据驻留分区**：按法域划分部署单元（至少分中国大陆和其他地区）。共享底座可以两边各自构建；用户私域和个人信息不跨区。
10. **DI-10 v2 需要新增的 AC-0 条目（草案）**：
    - AC-0.6：私域到共享层无数据路径，用静态检查加数据流测试验证；
    - AC-0.7：共享层中不存在 license 不在白名单内的全文或图；
    - AC-0.8：全平台 arXiv 请求间隔不小于 3 秒；
    - AC-0.9：所有 LLM 输出都带显式和隐式标识；
    - AC-0.10：不存在跨用户复用凭证的代码路径；
    - AC-0.11：推荐页提供非个性化模式，标签可删除。
11. **DI-11 00-requirements 需要以 ADR 修订**：第 6 条"多用户非目标"改为"多用户平台在 HC 约束下提供"；第 3 条"不再分发"细化为 HC-01、HC-05、HC-16；第 5 条（Google Scholar）保留。
