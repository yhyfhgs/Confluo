# 09 · 路线图与里程碑

> 本文回答 v2 先做什么、做到什么算完成、什么时候要用户拍板。结论：按"合规闸门 → 数据 → 算法 → 界面"的顺序分八个里程碑（V0–V7）推进，V5 出口即 v2.0 公开内测。全程 113 张任务卡、约 599 人日、243 条正式验收。人日与日历只是规划估算，里程碑以验收判定完成，不以日期判定。

## 要点

- **八个里程碑，先底座后体验**：V0 基线 → V1 语料底座 → V2 检索与路由 → V3 多用户平台（与 V2 并行）→ V4 推荐 R0 → V5 前端 PWA → V6 社交、匹配与推荐 R1 → V7 规模化与加固。
- **v2.0 公开内测 = V5 出口**：[01](01-vision-and-requirements.md) 的 48 条 Must 全部通过验收，AC-0 红线全绿，可用性测试 P0 问题为 0。V6 对应 v2.1，V7 对应 v2.2。
- **工作量**：113 张任务卡、约 599 人日；3 条泳道并行时约 30 周到 v2.0、约 38 周到 V7（±50%）。节奏主要由外部等待决定，编码不是瓶颈。
- **验收**：243 条正式 AC，另有贯穿全程的 18 条 AC-0 红线；FR-17…FR-87 与 NFR-9…NFR-27 共 90 条需求，每条至少对应一条 AC。
- **决策门**：DG-Q4 在 V1 开工前确认，DG-Q7 在 V1 出口定型；DG-Q1、DG-Q2 最晚在 V5 公开内测前；DG-Q5、DG-Q6 在 V6 前；DG-Q3 在 V7 或预算告警时。
- **ADR 先行**：37 条 proposed ADR（D-040…D-076，见 [ADR 登记](../decision-log.md)；D-074…D-076 为 2026-09-30 补入的连接器决策）是 V0 的第一项工作，由用户逐条裁决；实现期新决策从 D-077 起编号。
- **v1 双轨**：v1 维护冻结、全程可用；迁移分步进行，每步可回滚，任何一步都不写 v1 库。
- **编排**：一卡一分支一个实现 agent，另一实例独立评审（安全与合规类双评审），主 agent 作为 controller 跑门禁、合并、打 tag。

## 总体策略

排序原则：合规闸门先于数据，数据先于算法，算法先于界面。

- **闸门先行**：v2 从个人工具变成平台运营者。出站网关、策略引擎、数据四域与 RLS（行级安全，按用户隔离数据库行）的不变式若晚于数据落地，就得回头清洗已入库的内容，例如已进入共享派生的 B 类摘要（出版方持有版权、公开分发的摘要）。所以 V0 先立骨架与不变式测试，V1 在闸门之内收割，V3 在 RLS 之内接入用户。
- **先收割、后联邦**：卡片流、最新论文、频道与新论文分发只读本地语料，联邦检索只补即席查询的覆盖缺口。V1 的语料是 V2 检索与 V4 推荐的共同输入。
- **评测先行**：V1 建分学科金标（每学科 ≥200 条），同一批金标服务表示模型选型（V1）、检索回归门（V2）与推荐离线评测（V4）；V4 第一次下发就记曝光日志并跑 A/A 测试。
- **最窄竖切**：每个里程碑都产出端到端可运行的切片；前端从 V3 起用 mock API 预研，不等后端完工。
- **外部依赖左移**：发函、法务委托、用户之声调研放在 V0，因为等待最久。
- **降级算完成**：每项能力的完成标准都含降级路径，如替补链、非个性化回退、LLM 全不可用。
- **纯 CPU 规划**：T1 档（≤1,000 活跃用户）默认不配 GPU，推荐与检索重排按纯 CPU 设计；涉及用户画像的 LLM 功能推迟到 V6，且默认关闭。
- **发布门槛只含 Must**：Should 不设发布门槛；Could 只在前置条件满足后立项（V6、V7）。

关键路径是 V0 → V1 → V2 → V4 → V5。V3 与 V2 并行，只要在 V4 开工前完成事件接入与用户数据。

不在 V0–V7 范围：原生移动端（v2.x 候选）；推荐 R2 序列模型（达到升级阈值后另立里程碑）；下一规模档的架构演进（以 V7 的评估为输入另立计划）。

## 里程碑

每个里程碑除下列出口条件外，还须满足通用完成标准（见"组织方式与流程"）。

### V0 基线：设计定稿与工程底座

- 目标：把 ADR 与设计文档推进到可开工状态，立起"出错就明确失败"的工程底座。
- 交付：书面确认发函（NCBI、EMBL-EBI 含 Europe PMC 用量、OpenReview 优先），建确认登记与 robots 例外附表；离线 CI 门禁（许可、SBOM、秘密扫描）；docker compose 双部署与网络隔离；PG 18 四个 schema、RLS 模板与迁移工具；SourceSpec v2（来源的机读声明）schema 与 13 条 lint，转换 62 个 v1 VenueSpec，导入 187 行名录种子；策略引擎骨架与黄金决策表；出站网关骨架（主机白名单、robots 先行、诚实 UA、出站日志、拒绝用户侧通道）；API 骨架与契约测试；demo 可用性测试（5–8 人 × 3 学科）与第一轮用户之声调研。
- 规模：62 人日，15 张卡，29 条 AC，约 4 周。对外：无。
- 出口：ADR 全部有裁决；01–09 与[支持名录](../../catalog/source-directory.md)转为 approved；platform 与 personal 两种部署在参考机上启动且健康检查全绿；用户确认 DG-Q4；证据逾期的 30 天宽限经主 agent 复核；01 的设计目标值按实测校准后固化。
- 连接器工作流（W0）：冻结连接器接口契约 v1，立起连接器 SDK、一致性套件与经网关录制的 fixture 工具，用 `crossref_delegated`、`arxiv_oai`、`europe_pmc_rest` 三个参考连接器打通全链。出口为这三个及前置件 `crossref_rest`、`oai_pmh` 达一致性等级 CL1，并各经网关完成一次 dry-run。所需约 22 人日未计入本节规模，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V1 语料底座与 P0 来源

- 目标：在策略引擎与出站网关之内，把 P0 来源（首批优先接入的来源）稳定收进本地语料，并定型表示模型。
- 交付：网关礼貌与稳定性（共享令牌桶、AIMD、重试预算、熔断、挑战冷却、舱壁）；策略闸门与漂移探针（监测 robots 与条款变化）的分档降级；connector 框架，包装 20 个 v1 adapter；零代码 venue 接入（登记后由 Crossref 代理元数据）；P0 新 connector 与批量快照导入；增量收割；身份去重与金标；摘要补齐与权利分级；主题标注；嵌入与分学科表示评测；共享 TL;DR 三道闸；许可闸与商用开关；审计日志哈希链；成本账本。
- 不做：检索 API 与用户侧取回。取得书面确认前，不对 NCBI 等冲突主机做后台收割，也不做 OpenReview 平台共享收割。
- 规模：125 人日，19 张卡，41 条 AC，约 8 周。对外：无（staging 持续收割）。
- 出口：OpenAlex 快照子集已导入，并与起步 100–300 万 work 的目标比对；P0 增量收割在 staging 连续 ≥14 天无全局失败；DG-Q7 定型并登记；相关 AC-0 在真实收割日志上复核通过。
- 连接器工作流（W1、W2）：P0 平台侧的族引擎、专用连接器、快照导入与 v1 平台侧桥接，加 OA 定位替补 `unpaywall_api`，共 29 个。出口为无闸门的 P0 平台侧连接器达 CL3，受书面确认闸门的停在 CL1 待命，每个桥接写明去向与移植期限。其余 8 个 v1 adapter（转用户侧、暂停与 P1 的）随 V3 处理，与上面"包装 20 个"的口径差及人日差额见[连接器实施计划](connectors/implementation-plan.md#未决事项)。

### V2 检索与路由

- 目标：让本地语料可查、可筛、可组合、可订阅。
- 交付：Query AST（五种意图：精确查找、检索、相似、最新、引文扩展）与 v1 订阅兼容；查询解析；本地混合检索（BM25 + 向量，RRF 融合，cross-encoder 从 int8 小模型、top-50 起步）；图查询与相关论文；TSRG（主题-来源路由图，决定查询该问哪些来源）与路由器；健全放宽（来源不支持的条件先放宽成超集，再在本地精筛）与联邦执行（总截止 3 s，流式补齐）；WatchKey（多用户共享的收割键，同键只收一次）编译与新鲜度调度；Percolator（新论文入库时反查该推给谁）；检索与频道 API（单租户开发账号）。
- 规模：78 人日，15 张卡，46 条 AC，约 6 周。对外：无。
- 出口：300 万 work 上本地检索端到端 p95 ≤800 ms；14 日在线新鲜度观测完成；检索回归门接入 CI；WatchKey 编译取代 V1 的系统频道调度；路由日志与路由训练集的去标识方案通过出口前隐私评审。
- 连接器工作流：平台侧 v1 桥接在本里程碑出口前移植到目标族或退役（CLX）；路由器与健全放宽消费各连接器生成的 SCD，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V3 多用户平台

- 目标：把单租户底座变成可邀请他人使用的多用户平台。
- 交付：账号与认证（邮箱/密码、ORCID OAuth、MFA、年龄声明、同意记录）；用户域全表 RLS 与越权测试；频道、文献库、关注与屏蔽；事件接入；数据导出与删除；题录导入；浏览器配套扩展（在用户本人浏览器中取全文，先做 Chromium 系）；pc-agent（用户本机代理）与 personal 本机取回；端到端凭证库与多设备同步；管理员控制台（默认只经 VPN 或 SSH 隧道访问）与来源登记审核；备份恢复（PITR、拉取式异地备份）；v1 → v2 完整 ETL；P1 来源第一批（经管与聚合，泳道任务）。
- 规模：89 人日，15 张卡，29 条 AC，约 6 周（与 V2 重叠约 4 周）。对外：邀请制内部封测，只开检索、频道与文献库，推荐为非个性化。
- 出口：RLS、导出删除与出站审计全绿；相关 AC-0 在多用户数据上复核通过；名录快变事实的首次季度复核完成。
- 连接器工作流（W3 批次一）：用户侧配方与用户 key 连接器 10 个（其中 3 个待 P-13 只占位）、P1 第一批 14 个。出口为用户侧 P0 通道达 CL3（具名禁止 AI 爬虫的站点在法务结论前只给"在出版社打开"与打开后一键保存），P1 第一批达 CL3，管理员控制台先做来源申请审核、策略与漂移只读、证据复核队列与简版健康表，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V4 推荐 R0 与 Feed API

- 目标：用本地语料与用户事件，做出第一版可解释、可控、可评测的个性化批次。
- 交付：候选管线与多路召回；用户模型（兴趣树节点权重、多质心、每用户逻辑回归）；打分与重排（ValueModel 按行为价值加权打分，多样性重排，探索槽，净负分沉底）；逐事件在线学习与回滚；冷启动后端；新论文分级曝光与曝光下限（只对资格集合，≤5% 预算，见 D-063）；读者↔论文与论文→读者两层匹配；理由码、非个性化模式、兴趣标签与原理公示页；私有评分与笔记；Feed API（有限批次，默认 25 张）；评测平台（曝光日志、离线回放、A/A、交错对比）；隐私聚合与 k 匿名闸（不足 k 个不同用户不入模、不展示）；1 万模拟用户压测。
- 规模：77 人日，15 张卡，34 条 AC，约 6 周。对外：dogfood，维护者与少量受邀用户用 demo 客户端或早期 PWA 试用。
- 出口：离线评测与 A/A 通过；dogfood ≥2 周且护栏看板无持续越界；k 参数初值经主 agent 确认；分级曝光与校准的隐私边界通过出口前隐私评审。
- 连接器工作流：不新增连接器；已达等级的保持条件持续有效，失效即自动降级，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V5 前端 PWA 与可用性

- 目标：交付简单、顺滑、可访问的 PWA，并用真人测试与内测证明可用。
- 交付：React 19 PWA；Deck（今日分拣卡叠：手势判定、状态机、动效、减弱动态效果、低端降级）；卡片、详情、收藏库、搜索页；首屏样本卡组与引导；透明与控制；离线发件箱；用户侧全文界面；可访问性（WCAG 2.2）与中英双语；E2E、视觉回归与真机测帧；可用性测试（5–8 人 × 3 学科）与 ≥7 天内测；发布前安全与合规审计；P1 来源第二批（泳道任务）。交互规范见 [07](07-frontend-interaction.md) 与 [demo](demo/paper-feed-demo.html)。
- 规模：83 人日，17 张卡，46 条 AC，约 6 周（前端预研自 V3 起）。对外：v2.0 公开内测，PWA 公开注册或继续邀请制（取决于 DG-Q1），同时发布 personal 部署。
- 出口：48 条 Must 的 AC 全部通过；AC-0 全绿；可用性测试 P0 问题为 0；公开内测前安全审计通过；DG-Q1、DG-Q2 已定案或经用户确认按默认发布；隐私政策、条款与推荐原理公示页定稿。
- 连接器工作流（W3 批次二）：P1 第二批 10 个达 CL3；用户侧全文界面覆盖取回回执与"为什么没有全文"的全部状态，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V6 社交、双向匹配与推荐 R1

- 目标：在门禁满足时开放公开评论与评分、社会证明与研究者匹配，并按升级门把推荐推进到 R1。
- 交付：研究者匹配需求访谈（决定是否立项）；公开 UGC 前置能力（实名锚定、审核巡查、举报处理、DMCA 代理、反作弊、AI 内容声明、附件与链接拦截）；公开评论与评分；差分隐私决策与公开计数（见 D-064）；研究者匹配 opt-in；推荐 R1（多行为 GBDT/LTR、协同召回、Thompson/LinUCB 探索）；R1 的 LLM 功能（自托管，默认关闭）；检索个性化与分享卡。
- 规模：48 人日，8 张卡，11 条 AC，约 5 周。对外：v2.1，各功能受各自门禁控制。
- 出口：门禁未满足的功能保持关闭、入口不渲染；R1 须在离线与在线双重对照中显著胜出才全量，否则 R0 继续服务，不阻塞出口。
- 连接器工作流（W4）：P2 与登记来源按申请量在维护余量内按需升级，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

### V7 规模化与加固

- 目标：按 1 万用户的容量设计验证系统，建立 SLO 与运维节奏，完成安全加固。
- 交付：容量压测与升级触发评估；SLO 监控、runbook 与季度灾备演练；不锁定演练与导出往返；独立渗透测试与密钥轮换；成本复核与 DG-Q3 询价；只读 API 与 MCP；私有资产同步（法务有结论后）；personal 部署的 OA 批量取回（只在用户本机部署写入私有空间）；名录扩展。
- 规模：37 人日，9 张卡，7 条 AC，约 4 周。对外：v2.2 稳定版。
- 出口：核心读路径连续 30 天可用性 ≥99.5%（设计目标）；渗透测试高危项清零；DG-Q3 已决策或记录按默认继续的理由；前置条件未满足的 Could 项保持关闭。
- 连接器工作流（W4）：P2 来源的连接器按需升级到 CL2 以上，只在维护余量内放行；运维台的连接器详情、灰度与预算界面在此补齐，见[连接器实施计划](connectors/implementation-plan.md#里程碑对应表)。

## 总量

- 任务卡 113 张，约 599 人日。1 人日指一名熟练工程师一天的产出，含测试、fixture、文档与评审回修；新 connector 按 ≤2 人日/个、零代码接入按 ≤30 分钟/本估算。
- 正式 AC 243 条（V0 29、V1 41、V2 46、V3 29、V4 34、V5 46、V6 11、V7 7），由各设计文档的 366 条草案判据合并而来：同一判据跨文档只留一个编号，判定取各草案判据的合取。
- AC-0 红线 18 条（AC-0.1…AC-0.18），贯穿全部里程碑，任一违反即整体不通过。
- 连接器工作流按[实施计划](connectors/implementation-plan.md#与-09-和长稿任务卡对账)比对应任务卡多约 88 人日，未计入上述总量，待 V0 出口重估。
- 参考日历已计入 V2 与 V3、V3 与 V5 的重叠。固定等待有：书面确认回复、法务意见、两轮真人可用性测试、14 日在线新鲜度观测、≥7 日内测、月度恢复演练。

## 决策门

门未关闭时，依赖它的任务卡不得开工；按默认假设继续须记录理由。

- **DG-Q1 是否商业化或 SaaS 化**：V1 表示评测开工前先确认默认（评测要用非商业许可的数据集），最晚 V5 公开内测前定案。默认否：非商业、自托管或邀请制，依赖按可能商用的最严口径选型。
- **DG-Q2 是否面向中国大陆公众运营**：V5 公开内测前定，公开评论（V6）前复核。默认否：算法推荐合规能力按最严口径内建，备案类义务留到上线决策。
- **DG-Q3 是否购买 OpenAlex 付费档或 Crossref Metadata Plus**：V7；OpenAlex 美元预算连续 2 周触发 80% 告警时提前。默认否：免费季度快照加增量 API。
- **DG-Q4 robots 与官方 API 文档冲突时怎么办**：V1 开工前（V0 出口确认）。默认保守：后台批量须先取得书面确认；低频、用户触发的单篇调用须先登记进 robots ADR（D-049）的例外附表，D-049 接受前连按需调用也不做。放宽只能逐站进行。
- **DG-Q5 双向匹配先做哪种**：读者↔论文、论文→读者在 V4 开工前定；研究者↔研究者在 V6 访谈后定。默认先做前两种，研究者匹配做成默认关闭的 opt-in 实验。
- **DG-Q6 评论是否公开**：V6 开工前。默认 v2.0 只有私有笔记与私有评分；公开评论与评分在 V6，前提是实名锚定与审核能力就绪。
- **DG-Q7 表示模型选型**：V1 出口，最晚在 V2 建向量索引前。默认在 gte-large、Qwen3-Embedding-0.6B、SPECTER2 中按分学科评测（每学科 ≥200 条金标）选定。

选非默认的主要代价：DG-Q1 选商用，受限来源停用，须补书面商用许可，表示评测改用非 NC 数据；DG-Q2 选面向大陆，要增设中国单元与境内存储，LLM 改用已备案或自托管模型，公开评论改后台实名，v2.0 顺延；DG-Q6 选不公开，V6 约减 16 人日。

## Top 10 风险

括号内为概率/影响。

1. 上游条款漂移，书面确认迟迟不到（高/高）→ V0 即发函；走替补链（Europe PMC；arXiv 加 dblp 快照加 OpenReview 外链）；漂移探针分档降级；关键能力至少两条同能力通道。
2. 法务结论缺位，B 类摘要、扩展取回、私有同步等无法放宽（高/中）→ 全部按从严默认实现，保留可逆开关与定向重建，功能开关默认关闭。
3. 上游限速与计费收紧（OpenAlex 按美元计费、Crossref 分池、arXiv 限流）（中/高）→ 快照底座加兴趣并集子集；WatchKey 去重；美元预算桶；付费档作杠杆。
4. 分学科表示与检索质量不达标（数学公式、JEL、化学实体、中文）（中/高）→ V1 分学科评测；BM25 兜底；多模型版本并存，按学科选表示。
5. 卡片分拣形态不被研究者接受（中/高）→ V0 前置 demo 可用性测试；有限批次；列表视图实验桶；交错对比验证。
6. 用户少、反馈稀，R0 学不动、实验无统计功效（高/中）→ 共享论文嵌入与内容先验；冷启动主动学习；交错对比与留出组；离线指标只作护栏。
7. 隐私与越权缺陷，如 RLS 漏表、私域数据流向共享、凭证泄露（低/高）→ 四域不变式从 V0 起测；数据库全表越权测试；金丝雀令牌；AC-0 阻断；安全与合规卡双评审。
8. 纯 CPU 下性能预算不达标，或 BM25 扩展 pg_textsearch 不成熟（中/中）→ 预计算快路径；int8 小模型与流式补发（降级占比 ≤5%）；保留 tsvector/GIN 与 ParadeDB 可选项。
9. 范围蔓延与评审吞吐瓶颈（71 条 FR、243 条 AC、37 条 ADR、113 张卡）（高/中）→ 按 Must/Should/Could 切分，v2.0 = V5；Could 满足前置才立项；波次管理与评审模板。
10. 浏览器与 PWA 限制，如 iOS 不支持扩展、iOS PWA 帧率、扩展商店审核（中/中）→ "在出版社打开"永远可用；pc-agent 作替代；真机测帧与降级阶梯；先做 Chromium 系。

## 组织方式与流程

沿用 v1 流程规范（archive/v1）的"任务卡 + 独立评审 + controller 合并"编排。

- **角色**：用户裁决 ADR、决策门与对外事项（发函签名、商用许可），并确认里程碑出口。controller 由主 agent 担任：拆卡、派卡、排波次、跑门禁、合并、打 tag、写里程碑报告。实现 agent 一卡一分支；独立评审由另一实例担任，安全、隐私、合规、迁移类卡双评审；调研 agent 只写指定路径，不改设计文档。
- **任务卡**：写明目标、范围、依赖与决策门、承接的设计章节（须已 approved）、关联 AC、估算与评审方式；里程碑开工时写入 `docs/plan/v2/implementation/v<m>-plan.md`。
- **评审循环**：实现 → 独立评审（亲自构造对抗输入，结论为 APPROVE、NEEDS_FIX 或 NEEDS_DECISION）→ 回修 → 同一评审复核 → controller 在干净环境跑门禁后合并。两轮未过，由 controller 决定拆卡或换模型档。
- **设计变更**：实现中需要实质修改设计时，先把文档降回 review 或新写 ADR，不在实现分支里静默改设计。
- **波次**：每个里程碑拆 3–5 个波次：地基卡（接口、schema、契约）→ 并行卡 → 验收批 → 跨卡独立审计与修复 → 文档收尾。数据库 schema、事件契约、策略引擎等共享核心的卡串行；connector、前端组件天然并行；泳道任务（P1 来源、前端预研）不占关键路径的评审容量。
- **模型选择**：设计关键、安全隐私、合规、核心算法、迁移与跨卡审计用最强档，其余用标准档；评审档不低于实现档。
- **门禁**：`make check` 为提交门禁，断网可跑，核心覆盖率 ≥80%；在线、浏览器、压测用例只在显式命令下执行。
- **通用完成标准**：全部卡经独立评审后合并，无未关闭的 P0/P1 级评审意见；本里程碑 AC 全部通过，证据写入验收记录，适用的 AC-0 全绿；"有条件通过"须写明条件与期限，且不能用于 AC-0 和安全、隐私条目；同步文档状态、INDEX、GLOSSARY 与 progress；写里程碑报告与 session 日志；下一里程碑的决策门已关闭或已记录理由；用户确认后打 tag `v2-v<m>`，v2.0 公开内测另打 `v2.0.0-beta.1`。

## v1 → v2 迁移

v1 维护冻结：只修缺陷、不加功能，在 v2 全程可用，是 v2.0 之前 personal 场景的正式工具；新需求一律登记为 v2 FR。v1 代码与流程规范在分支 `archive/v1`，只作只读 ETL 源和 pc-agent 的复用库。

原则：只读访问 v1 库；每步写入独立目标，回滚即丢弃后重跑；索引、向量、cluster 等派生结构在 PG 侧重建；权利从严：无法证明为 A 类或 B 类的摘要不进共享层，v1 的 PDF 只在用户本机的 personal 部署进入私有空间，v1 凭证不迁往任何服务端。

1. 冻结与盘点（V0）：记录 v1 库现状（179 篇、228 个标识符、2 个订阅）。
2. 注册表迁移（V0）：62 个 VenueSpec 转为 SourceSpec v2 与 Venue 声明，并入 187 行名录种子。
3. 订阅转换（V2）：9 个预置包与存量订阅转为频道模板，筛选结果须与 v1 逐条一致。
4. 公共部分 ETL：V1 干跑到 staging，V3 正式写入共享层并重建 cluster 与索引。
5. 私有部分与凭证分流（V3）：迁移用户的频道、文献库与种子进本人私域；部署级 key 进网关秘密存储，用户级凭证只进本机凭证库。
6. 双轨观察（V3 出口到 V4）：v1 与 v2 频道并行 ≥14 天比对命中，差异须为零或逐条可解释。
7. 切换默认（V5 出口）：用户改以 v2 为主，v1 保留为离线工具与 OA 批量取回工具。personal OA 批量取回（V7）上线后，由用户决定是否把 v1 标为 deprecated。

## 怎么验收

- 本文的验收并入 V0：ADR 定稿（AC-V0.1）、设计文档定稿（AC-V0.2）、路线图自洽（AC-V0.3）。自洽由脚本校验并纳入 `make check`：每条 FR/NFR 至少一条 AC，每条 AC 恰属一个里程碑，Must 的 AC 都在 V5 或更早，每张任务卡写明依赖、估算与承接章节。
- 每个里程碑按通用与专项完成标准判定出口，逐条 AC 证据写入验收记录；AC-0 任一失败即整体不通过。
- 不可退化的回归门：检索任一学科 nDCG@10 下降超过 2 个百分点、许可闸出现误放行、RLS 任一越权用例失败，都会阻断。
- 测试类型沿用 v1 的六类（单元、契约、fixture 回放、集成、在线冒烟、runbook），新增八类：属性与仿真、离线基准、在线实验、压测与故障注入、RLS 与安全回归、合规审计、前端与视觉回归、可访问性与可用性。
