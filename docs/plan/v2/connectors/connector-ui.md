# 连接器 · 接口相关的增量 UI

> 本文回答：连接器接口标准落地后，读者在哪里看到"来源能给什么、为什么没有全文、我的连接怎样"，部署方在哪里看连接器健康、策略漂移与复核队列。
> 结论：不加一级 Tab。读者面挂在"我 → 全文与连接""我 → 来源"和四个情境入口上；PWA 不收任何凭证，"可用你的权限"只在扩展或 pc-agent 本地计算。运维面是独立的 api-admin 控制台，V3 只做 O7、O3 只读、O4 与简版 O1，其余到 V7。状态一律"图形 + 文字 + 颜色"，运行故障与"按来源规则调整"分两套词汇；降级即时可见，规则类下调须人工确认升档才撤下。

## 要点

- U1–U7 是 [07](../07-frontend-interaction.md) 的细化：一级入口、卡面 6 项与"刻意不做"不变，卡面不加来源或健康标记；O1–O7 属独立的运维控制台。
- 状态唯一来源是契约的 `EffectiveStatus{cl_declared, cl_effective, health, policy_mode, reasons[]}`，按 (connector, endpoint, channel) 计算（[contract §13](contract.md#13-可观测性与-effectivestatus)）；U1、U3、U7 与 O1 读同一份数据，词汇不同。
- 连接状态七态加终态，只由扩展或 pc-agent 判定；取回回执五类，各配一条合法退路；原因码六类，每类都带"在出版社打开"。
- 不做：红点、分拣中途弹窗、PWA 凭证输入框、逐源重试、批量取回、他人权限提示、来源 logo。
- 用户侧回执不进任何跨用户统计，运维台不显示用户侧成功率（[08](../08-compliance-security-privacy.md#执行位置与凭证)）。

## 设计原则

继承 07 的全部原则（[07](../07-frontend-interaction.md#设计原则与刻意不做)），本增量另加五条：

1. **透明**：非正常状态写"原因、对你的影响、下一步"，不写可被用来规避的细节。
2. **不暗示绕过**：下一步只列合法路径（开放版本、你的 key、机构访问、在出版社打开）；黑名单词：绕过、破解、镜像、解锁、一键获取、免费下载。红线不做成任何开关。
3. **明文凭证不离端**：PWA 没有 key、token、EZproxy 前缀或口令输入框；条目名与状态经本机消息取得，只在内存渲染；多设备同步只传端到端密文（D-054）。
4. **状态可解释**：状态词都能追溯到 `EffectiveStatus.reasons`、回执或原因码，运维台可再追到证据与审计。
5. **只降不升可见**：降级下次刷新即出现；规则类下调等 O3 记下双人确认升档才撤下，不显示"即将恢复"；运行故障随 `health` 恢复（急停、`suspended` 由 owner 解除），与路由同源。限速与冷却是礼貌行为，只显示剩余时间（HC-10）。

## 入口与信息架构

| 屏 | 入口 | 交付 |
|---|---|---|
| U1 来源 | 我 → 来源（"显示"之后）；来源页用 Sheet | V5 |
| U2 我的连接 | 我 → 全文与连接（即 07 的"全文取回"组） | 扩展与 pc-agent 自身界面 V3；PWA 组 V5 |
| U3 来源范围 | 搜索完整性一行 → 逐源 Sheet；来源筛选条；频道编辑器 | V5 |
| U4 可得性说明 | 详情"阅读 ▾"与"来源与署名" | V5 |
| U5 取回状态与回执 | "阅读"按钮内进度与下方结果块（`.explain` + `.steps`） | V5（扩展侧 V3） |
| U6 申请新来源 | 我 → 来源 → 申请；搜索空结果与部分结果页的低强调链接 | V3 接口复用"申诉"资源的新类别并进 O7；读者入口与完整状态流 V5 |
| U7 来源状态通知 | U1 状态历史；频道、来源筛选浮层的小字；可选 digest | V5 |
| O1–O7 | api-admin 控制台 | V3：O7、O3 只读、O4、O1 简版；V7：O2、O5、O6 |

- **读者面**：宽屏时来源页用右侧窗格；URL 不带检索词、申请单号或用户标识。
- **运维面**：只经 VPN 或 SSH 隧道、强制 MFA，只看假名化聚合，下钻个人数据须工单授权并审计（[08](../08-compliance-security-privacy.md#安全威胁模型)）。角色提案：viewer 只读，reviewer 处理 O4、O7，operator 发起升档与急停（V3 走管理 CLI，D-042、长稿 02 §6.5）；提交人不能批准本人条目（四眼，D-076），动作全审计（HC-28）。视觉用 `--pg-*` 外壳，单独打包。

## 读者面逐屏

通用规则（各屏未另写的移动端与可访问性要求）：状态词 13/18 加 14 px 图标；行高 ≥48，触控 ≥44 pt；状态变化用 `role="status"` 礼貌播报、不抢焦点；320 px 与 200% 放大不丢功能；窄屏筛选收进底部 Sheet；只用 150/100 ms 淡入淡出；亮暗两套 token。

### U1 来源

- **目的**：看懂每个来源"能给你什么、现在怎样"，管理关注与屏蔽。
- **元素**：①我关注的来源，新增"＋ 关注来源"选择器（数据来自 `/sources`）；②屏蔽与少推（与"兴趣与关注"同一列表）；③来源名录，按学科与七类筛选，七类用读者文案：出版平台、标识与注册、期刊与会议、预印本与工作论文、其他一手产出、文献库与仓储、检索与聚合（[七类](../../../catalog/source-taxonomy.md#七类定义)）；④申请与我的申请（U6）。
- **名录行**：来源名（纯文字，不用 logo、不取 favicon）· 类别 · 三枚通道徽标（元数据 / 新论文 / 全文，各带模式词）· 状态词（正常不显示）。
- **来源页**：三通道各一行"模式词 · 健康词 · 它能给你什么"，如（示意）"新论文 · 自动收录 · 每天收录新预印本"；"全文 · 仅外链 · 在 arXiv 阅读"。另有数据时点、替补、署名与"列出来源不代表来源方认可"（HC-24）、关注 / 少推 / 屏蔽、状态历史（U7）。
- **分级**：`support_tier=登记` 写"已登记，未单独维护通道，可能经 Crossref 或 OpenAlex 间接覆盖"；`link-only`、`user-import-only` 写"只能外链""只能自行导入"；`excluded` 不列出。
- **空态与异常**：无关注时给选择器；失败或离线用缓存并标"名录时点"。

### U2 我的连接

- **目的**：知道全文取回靠什么执行、凭证在哪、现在能不能用。
- **行**（名称、状态点、状态词、副文字）：
  - 配套扩展：握手 `pc.hello` → `pc.hello.ok{ext_version, api_compat}`；超出 N-1 兼容为 `error`"扩展版本过旧"。
  - 本机代理 pc-agent：本机接口校验令牌、Host 与 Origin；personal 部署注明 `host_is_user_device`。
  - 我的 key 与机构条目（只读）：如"Elsevier TDM key · 在 pc-agent""Springer Nature API key""Wiley TDM token""NASA ADS token""OpenReview 令牌""某大学图书馆 · EZproxy"；全集随 `exec_side=user` 的连接器（另含 `lens_api`、`alphaxiv_mcp`、`orcid_api`）；不显示任何密钥或前缀原文；扩展未连接时只留"连接扩展后可查看"。
  - 已授权的出版商域：数量、冷却中的域与剩余时间、各域今日用量 / 200。
  - 本机私有副本：篇数与占用；管理、全部删除（toast 撤销，不弹框）。
  - 说明："取回在你的浏览器或本机完成，平台看不到、也解不开你的凭证；每个出版商单独授权；遇到人工验证会停下交给你"。
  - 私有 PDF 同步、凭证多设备同步：特性开关开启且已同意才渲染；只同步 key 类凭证密文，会话 cookie 不同步（D-054）。
- **交互**：设置、编辑、测试、断开都深链到扩展或 pc-agent（`pc.settings.open`）；"测试连接"只在执行器内运行，计入端侧护栏（同域串行、间隔 ≥6 s、单域日上限 200），另限频（设计值每条目 10 分钟 1 次）。
- **提示位置**：`expiring`、`needs_reauth` 只在"我"页这一行和结束态卡上各出现一次，修复即撤下。
- **异常**：不支持扩展的设备（iOS 待核）写"此设备暂不支持配套扩展，'在出版社打开'照常可用"；握手超时（设计值 1.5 s）按未设置显示。
- **扩展与 pc-agent 自身界面（V3）**：选项页录入 key、token、EZproxy 前缀或 OpenURL 解析器（端到端加密）；逐域授权前说明"会做：只在你点击时取回当前论文；不会做：后台访问、读 cookie、批量下载"；断开即清除本机凭证。工具栏"保存当前 PDF"只在点击时生效（`activeTab`）。

### U3 来源范围

- **目的**：检索与频道里看清查了哪些来源、哪些没回来、为什么。
- **完整性明细**：结果顶部一行点开为逐源 Sheet：已返回 / 等待中 / 超时 / 限速中（约 N 分钟）/ 暂停自动检索 / 未查询，附估计覆盖率、截断与数据时点，字段来自 SSE `source_status` 与 `done`（[02](../02-architecture.md#api-面)）。
- **能力提示**：由 SCD 谓词支持等级生成一行小字，如"Crossref 只用于 DOI 查找与引文匹配，不参与关键词检索""该来源不支持关键词检索，将放宽后在本地过滤"（[04](../04-retrieval-and-routing.md)）。
- **来源筛选**：浮层列名录来源并带状态小字（"暂停更新 · 自 09-12""只能外链"）；只限制结果，不改选源路由。
- **频道编辑器**：列出来源；有暂停时写"5 个来源里 1 个暂停自动收录，已由 {替补} 补齐"。
- **不做**：逐源"重试"与"强制刷新"；用户可整体重新检索，受每用户每日联邦配额（初值 30 次，[02](../02-architecture.md#出站网关egress-gateway)）约束（见未决 5）。

### U4 可得性说明

- **目的**：在详情里一句话说清能不能读全文、为什么、下一步。
- **"阅读 ▾"**：主动作按 `FulltextOption.kind` 顺序 `oa_link > tdm_api > user_fetch > open_in_tab` 取第一项，其余进下拉，补"用本机代理取回"；具名禁止 AI 代理的出版商不给"用你的权限取回"，没有开放版本与本人 TDM 路径时只给"在出版社打开"，注"打开后可用扩展'保存当前 PDF'"。
- **版本**：按 `version_claim.stage` 标预印本 / 工作论文 / 接受稿 / 正式版（`preprint`、`wp`、`am`、`vor`），`unknown` 不标；开放版本注"可能与正式版不同"。
- **原因行**：没有可直接阅读的全文时，下拉底部显示原因码文案（状态机 §3）；连接问题另起一行显示 U2 状态。
- **"可用你的权限"**：扩展已连接且本机判定 `likely` 时才叠加到 OA 徽标；判定只在内存使用，不写 IndexedDB、不进事件。
- **"来源与署名"**：补"数据来源：{来源}（{通道}）· 获取于 {日期}"（HC-07 字段）。
- **异常**：离线时只保留已缓存外链与本机 PDF；`fulltext-options` 失败时只给"在出版社打开"。

### U5 取回状态与回执

- **目的**：单篇取回全程可见，失败时给合法退路。
- **进行中**（`.steps`，按钮内同步）：签发意图（5 分钟内有效）→ 交给扩展或本机代理 → 排队（"同一出版社两次取回至少间隔 6 秒"）→ 取回中 → 保存到本机。后四步由执行器以 `pc.intent.progress.stage` 回报（长稿 `opening | fetching` 补为 `queued | opening | fetching | saving`）；排队超过意图有效期即回执 `error`。
- **结果块**：五类回执各一句文案加一个退路（状态机 §3）；`challenge` 写冷却剩余时间、不给重试。`open_fulltext` 记法以 06 为准。
- **不做**：自动重试、"全选下载"、批量入口（HC-32）；意图过期时写"请再点一次'阅读'"，不静默重签。

### U6 申请新来源

- **目的**：提名缺失来源，全程不触碰该来源主机。
- **表单**：名称（必填）；网址或 ISSN / DOI 前缀（选填，注"审核通过前，平台不会访问这个网站"）；类型；学科；用途说明（≤500 字）。不收凭证、附件或 PDF（HC-16）。
- **查重**：只和已加载的名录与 venue 名录本地比对，命中写"已在名录：{状态}"并链到 U1；不在线校验网址、不抓标题或 favicon（[03 SOP](../03-sources-and-corpus-pipeline.md#新增来源-sop-与成本目标)）。
- **状态**：见状态机 §4；"我的申请"复用工单列表，结果只在本行显示。不显示"N 人也想要"，聚合人数只进 O7。

### U7 来源状态通知

- **目的**：降级、暂停与替补对读者透明而不打扰。
- **位置**：U1 状态历史（90 天）；频道与来源筛选浮层的小字；详情原因行（`paused_by_source_rules`）；可选 digest（默认关、每日至多 1 条、只含本人关注或频道用到的来源，与连接提醒共用额度）。
- **文案**：只写影响与替补。规则类以"按来源规则"开头，如（示意）"按来源规则，OpenReview 暂不做平台侧收割，改由 arXiv 与 dblp 快照兜底"（D-052），不用红色、"故障 / outage"与 logo（HC-24），确认升档后才写"已恢复 · {日期}"；运行故障写"暂停更新 · 自 {日期}"，`health` 恢复即撤下。

## 运维面逐屏

通用：桌面双栏，≤1080 单栏；手机只读并可确认告警，升档与审批只在桌面；状态三重编码、全键盘可达；列表按"需要人处理"排序：`needs_confirmation` 与证据过期 > 运行失败 > 熔断、冷却 > 延迟 > 其他。

- **O1 连接器总览**：一行 = connector × 通道；列：族、`cl_declared/cl_effective`、`policy_mode`、`health`、保护状态（熔断 / 冷却 / 限速）、证据状态、发布阶段、新鲜度（按来源自身节奏判"延迟"）、错误率、配额、最近探针。用户侧通道只显示策略与探针。V3 简版只含 CL、模式、health、证据与探针。
- **O2 连接器详情**：页签：请求与错误（error_class × 责任方）· 游标滞后 · 探针历史 · SCD 动态统计 · 策略判定（链到 O3）· 审计（FetchLog）· 卡片（链到族文档）。
- **O3 策略与漂移**：每通道五类信号上限与结构性上限（含 `cap_conformance`）→ 取最严 → 模式，附证据 `{url, verified_at}`、PolicyOverride 到期日与已执行的自动降级记录。告警分 Alerting / NoData / Error，区分"探针坏了"与"发现漂移"；合规信号立即降级；恢复只显示"待人工确认升档"，须第二人确认。
- **O4 证据复核队列**：`review_overdue`、`needs_confirmation`、30 天内到期的 PolicyOverride、合规字段第二人复核、升档申请、CL 保持条件失效；按到期与风险排序，四眼原则；条目只带证据快照与差异，不带用户数据。
- **O5 灰度与发布**：CL 晋级只经 PR，界面只读；`shadow → canary（≤10%）→ full`，守护指标与自动回滚；急停分运维 `disabled` 与合规 `policy_denied/kill_switch`，后者恢复须双人。
- **O6 预算与配额**：OpenAlex 美元账本（80%、100% 两线；连续两周 80% 提前 DG-Q3）；S2 每 key 速率；按主机令牌桶；Crossref 分池（`/members` 归池待核）。书面限额是固定上限线，不设"临时提额"。
- **O7 来源申请审核**：按规范化名称或 ISSN 合并的申请、假名化人数、对应名录行、升级门槛（[D-073](../../decision-log.md)）；动作：登记 / 转支持（进 SOP 与 O5）/ 不接入（理由模板）/ 合并。网址只作纯文本、不预览；通过前网关对该主机零请求（含 robots.txt，AC-V3.25）。

## 状态机与视觉编码

### 1. 连接状态（U2；对象：扩展、pc-agent、每个 key 或机构条目、每个域授权）

| 状态 | 进入条件 | 文案（示例） | 主动作 |
|---|---|---|---|
| `not_set_up` 未设置 | 未安装、未添加；设备不支持 | "未设置；开放版本和'在出版社打开'照常可用" | 设置 |
| `connecting` 连接中 | OAuth 2.1 + PKCE 授权或握手中 | "正在等待你在新标签页完成授权" | 取消 |
| `connected` 已连接 | 最近一次本机自检成功 | "已连接 · 最近一次成功：{相对时间}" | 测试、断开 |
| `expiring` 即将过期 | 有效期剩余少于阈值（设计值 7 天） | "{n} 天后需要重新授权" | 现在更新 |
| `needs_reauth` 需重新授权 | 回执或刷新表明认证失效 | "需要重新授权，其他功能不受影响" | 重新授权 |
| `limited` 受限 | 域未授权、冷却中、日上限用尽、来源只给外链 | "今天在 {域} 的取回已达上限，明天恢复" | 了解原因、在出版社打开 |
| `error` 出错 | 执行器离线、版本超出 N-1、握手异常 | "本机代理未运行" | 查看帮助、更新 |
| `disconnected` 已断开（终态） | 用户主动断开，本机凭证已清除 | "已断开，本机凭证已删除" | 重新设置 |

转移：`not_set_up → connecting → connected → expiring → needs_reauth → connecting`；`connecting` 取消或失败回 `not_set_up`（失败附原因）；`expiring` 点"现在更新"进 `connecting`；`connected ⇄ limited`；执行器异常进 `error`，恢复回原态；任一态可进 `disconnected`。

### 2. 通道模式与健康（U1、U3、U7、O1）

| `policy_mode` | 读者词 | `health` | 读者词 |
|---|---|---|---|
| `background` | 自动收录 | `healthy` | 不显示 |
| `on_demand` | 按需查询 | `degraded` | 延迟 / 部分不可用 |
| `user_side` | 仅在你的设备上取回 | `suspended` | 暂停更新 |
| `link_only` | 仅外链 | `disabled` | 暂停更新（维护） |
| `deny` | 不提供（"不接入"只作支持分级用词） | `retired` | 已停用 |

`health` 非正常属"运行故障"；模式因漂移、`needs_confirmation`、合规急停或证据过期低于 SourceSpec 基线属"按来源规则调整"，文案"按来源规则，暂时{模式词}"；`cap_conformance`（CL 保持条件失效）造成的下调按运行故障显示；两者并存各占一行。来源通道的状态取当前生效路由（主连接器或替补）的 `EffectiveStatus`，替补生效时附替补说明。读者看不到 CL、error_class 与证据。

### 3. 取回回执与原因码（U4、U5）

| 回执 | 文案 | 退路 |
|---|---|---|
| `ok` | 已取回，只保存在这台设备上 | 打开私有副本 |
| `no_entitlement` | 你的账号没有该论文的权限 | 在出版社打开 |
| `challenge` | 出版社要求人工验证，请在出版社页面继续；{域} 约 {h} 小时内不再代取 | 在出版社继续（无重试） |
| `handed_to_user` | 已在新标签页打开出版社页面，请在该页阅读或保存 | 扩展"保存当前 PDF" |
| `error` | 取回失败（执行器未响应 / 意图已过期，请再点一次 / 授权失效，见 U2） | 在出版社打开 |

|---|---|---|---|
| `no_legal_oa` | 未找到经核实的合法开放版本 | 没有找到经核实的开放版本 | 有机构访问可连接扩展 |

### 4. 来源申请（U6、O7）

## 度量

只用不含个人数据的聚合，跨用户数字满足 `k_show`：按作品计的服务端原因码分布（不含本机叠加的冷却与权限）；有缺源的检索占比；读者可见降级的次数、时长与误报率；申请处理时长与终态占比；告警确认时长、复核逾期数；各屏 RUM。禁止：每用户连接状态、回执成功率、权限判定、授权域、按来源切片的 `open_fulltext`。

## 怎么验收

- **可用性测试**（随 V5 的 5–8 人 × 3 学科）：①说出一篇论文为什么没有全文并在出版社打开；②连接扩展并复述"平台看不到我的 key"；③找出频道里暂停的来源与替补；④提交申请并找到状态；⑤遇 `challenge` 时选"在出版社继续"。阻断级问题 0，把规则调整读成故障的人 ≤1；运维 2 分钟内找出一条漂移告警并说明原因（设计值）。
- **可访问性**：WCAG 2.2 A/AA，1.4.1 与 4.1.3 专项；触控 ≥44 pt；320 px 与 200% 放大；全流程纯键盘；axe-core 严重项 0。
- **性能**（设计值）：U1–U7 按需加载，Deck 首包仍 ≤170 KB gzip；名录首屏 ≤1 s（4G 中端机）；原因行随详情到达；O1 两百行渲染 ≤1 s。
- **合规**：检查表逐条通过；"可用你的权限"与连接条目出现在发往平台的请求中为 0；黑名单词命中 0。
- **对应正式 AC**（长稿 09 §4）：运维台与申请审核 AC-V3.24…V3.26；端侧护栏 AC-V3.19；"可用你的权限"只在本地 AC-V5.31；"阅读"路径与退路 AC-V5.32；红线 AC-0.13、AC-0.18。
