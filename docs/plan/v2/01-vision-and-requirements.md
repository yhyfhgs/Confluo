# 01 · 愿景与需求

> 本文回答 v2 为谁做、做什么、做到什么程度、怎样算成功。v2 是面向研究者的跨学科论文发现平台：每天把值得看的论文做成一叠有限的卡片，用户靠滑动分拣；用户自己的机构权限只用于本人取回全文。需求共 71 条功能需求（FR-17…FR-87）与 19 条非功能需求（NFR-9…NFR-27），成功以"每周每个活跃用户的有价值阅读数"衡量。

## 要点

- 差异不在单项能力，而在组合：跨学科（含经管工作论文）、卡片分拣、学习型个性化、可解释推荐、用户自带权限取全文。
- 先收割、后联邦：卡片流、最新论文与频道只读本地语料；即席查询在本地覆盖不足时才查远端来源。
- 订阅全文只在用户显式触发时单篇取回、私有存放；平台服务器不代用户访问出版商。
- 71 条 FR 中 Must 48、Should 15、Could 8；缺任何一条 Must，v2.0（首个对外可用版本）就不发布。
- 每日批次有上限（默认 25 张），看完即结束；一级入口只有三个：今日、收藏、我。
- 北极星是每周每个活跃用户的有价值阅读数；使用时长与日活只作护栏，不作优化目标。
- v1 进入维护冻结，v2 提供一次性迁移并复用 v1 的来源适配器。

## 产品定义与定位

- 一句话：面向研究者的跨学科论文发现平台。它从合法来源持续收割论文，用可解释的个性化推荐把"今天值得看的论文"做成一叠卡片，用户靠滑动分拣；用户自己的机构权限只用于本人取回全文。
- 与现有工具的差别：机构登录取全文、滑动交互、经管元数据都已有先例；v2 不宣称唯一，价值在于五项能力的组合，加上经管工作论文的新鲜度与多用户私域合规。
- 部署：同一套代码两种部署。platform 是多用户平台，自托管或邀请制；personal 是单租户部署（`docker compose`），承接 v1 的个人使用。
- 形态演进：实验室自托管 → 邀请制托管 → 机构版；机构版也不由平台代理机构访问。

## 用户

画像依据调研证据构造，是假设而非用户研究结论，须经用户之声调研与 demo 可用性测试（5–8 人 × 3 学科）校准。

- 理科与 CS 研究者（CS/AI、数学与理论物理、化学与材料、生物医学、心理学）：每天分拣大量新预印本，跟进预印本到正式版。痛点是同一工作重复出现、质量信号分散、化学与心理学摘要大量缺失、数学摘要含 LaTeX 公式。
- 经管研究者（经济、金融、管理）：追工作论文（NBER、SSRN、央行等）的新鲜度与发表去向，按 JEL 细分主题，用机构订阅读正式版。痛点是主流推荐产品不覆盖经管、SSRN 只能外链、出版商摘要缺失；中文母语者需要中文速读。
- 跨学科研究者（如 CS × 经管）：核心目标人群，需要跨来源组合查询，也想找合作者。
- 部署与迁移方：实验室管理员负责部署、邀请成员、配置部署级凭证、设成本上限、处理来源漂移（robots 或条款变化）告警，最怕用户行为触发出版商条款导致整个机构被封；v1 个人用户要把库与订阅迁到 personal 部署，并继续在本机用机构凭证取全文。

## 典型场景

1. 通勤分拣：打开"今日"，右滑想读、左滑不感兴趣、上滑跳过、下滑撤回上一张，每个手势都有按钮与键盘等价；看完一批进入"今日已看完"。
2. 冷启动：新用户在按学科分层的兴趣树上勾选领域，用 ORCID 导入本人作品或导入 Zotero、BibTeX、DOI 列表，再做校准卡（≥5 张想读且 ≥3 张不感兴趣即可结束，最多 20 张），然后进入首批卡片；每一步都可跳过。
3. 跨来源频道：金融学者建"资产定价 × 机器学习"频道（频道即保存的查询加推送偏好），选 NBER、SSRN、arXiv q-fin 与三大金融期刊目录，加 JEL G12 与关键词，设每日上限；次日起新论文进入卡片流与 digest 邮件。SSRN 只取元数据并外链；多人订阅同一收割键时只收割一次。
4. 通过我的图书馆读全文：在 platform 部署点"通过我的图书馆阅读"，浏览器配套扩展在用户本人的浏览器会话中单篇取回；没装扩展时默认"在出版社打开"。平台不代取、不预取。
5. 新论文找读者：一篇新工作论文入库后，系统在日批中按主题与兴趣画像反向找到匹配的读者，写入其次日卡片；读者可设每日上限、静默时段与"本周不看此主题"。

## 与需求原话的差别

- "点赞"在界面上叫"想读"（右滑或 ♥），不显示点赞数。
- "留言、评价"在 v2.0 是只有自己可见的笔记与 1–5 星评分；公开评论与评分在 V6。
- "像刷小红书、抖音"：论文做成卡片，但每日批次有限、看完即结束；算法只借鉴机制，不以使用时长为目标。
- "双向匹配"先做读者↔论文与论文→读者；研究者↔研究者默认关闭。

## 功能需求

FR 按用户的四项需求与横切组织。Must 是 v2.0 的发布门槛；Should 期望具备，延期须写明降级方案；Could 须先满足写明的前置条件。

**来源与语料**

- FR-17…FR-20 来源登记：机读注册表生成公开的[支持名录](../../catalog/source-directory.md)；每个来源声明元数据、最新论文、全文三条通道，写明限速、robots 与条款结论及证据；期刊与来源分离，多数期刊只需登记、不写代码；v1 适配器经包装层复用。
- FR-21…FR-22 合规采集：策略引擎综合文档化 API、批量快照、robots、条款与 TDM 声明，取最严结论，决定请求能否执行、以何种方式执行；漂移探针发现变化即告警并降级；元数据按学科选主干（期刊以 Crossref 为主），批量快照按全体用户兴趣的并集建本地底座。
- FR-23…FR-27 语料加工：收割、规范化、去重识别、内容增强、建索引、反向匹配六段流水线，按作品、版本、载体三层识别身份；缺摘要时按出版方补齐并记权利类别；主题标注、嵌入与可共享的 AI 摘要（TL;DR）；九个学科组各有元数据、最新论文与开放获取（OA）定位通道；撤稿与评审状态等质量信号。
- FR-28…FR-30 用户侧来源：可关注或屏蔽来源与期刊；可提交新来源登记请求，部署方审核后才启用；可导入知网、PsycInfo 等导出的题录，只进本人私有库。
- FR-31…FR-33、FR-85、FR-87 全文：许可允许再分发的 OA 全文可共享；订阅全文只在用户侧单篇取回、私有存放；条款禁止的只给外链。platform 默认"在出版社打开"，另提供浏览器扩展；personal 部署跑在用户本人设备上时可本机取回（见 D-053）。私有资产与 personal 的 OA 批量取回为 Could。

**检索与多用户数据**

- FR-34…FR-44 检索：统一查询语法树，按五种意图处理——精确查找、关键词检索、语义相似、最新论文、引文扩展；关键词与向量混合检索；可编辑筛选条；本地不足时按主题-来源路由图（TSRG，按主题挑最值得查的来源）选源联邦，3 秒截止；频道可做并、交、差；中文自然语言查询、相关论文与期刊浏览为 Should。
- FR-45…FR-47、FR-84 多用户数据：数据分共享语料、用户私有、事件三域（另有运维域），私有域全表行级安全（RLS）；画像、频道、文献库、反馈与设置按人保存；v1 库一次性迁移；检索叠加个人排序为 Could。

**推荐、匹配与反馈**

- FR-48…FR-53 推荐与反馈：至少 5 路召回，候选带来源归因；排序分为各行为价值乘以预测概率之和，净负分沉底、不补满批次；左滑是弱负反馈，"不感兴趣 + 原因"是强负反馈、当次会话生效；起步模型为共享论文表示加每用户逻辑回归，纯 CPU；默认留 10–20% 探索槽并标注；新论文曝光下限只给资格集合，全局预算 ≤5%（见 D-063）；反馈须绑定曝光记录（冷启动种子除外）。
- FR-54…FR-57、FR-61 社交与透明：v2.0 的评分与笔记只本人可见；公开评论与评分在 V6（Could），需实名锚定与审核；每张卡带推荐理由，经卡片上的 i 按钮查看；兴趣标签可看、可调、可删；从卡片流顶栏一键切到非个性化视图；社会证明须满足 k 匿名（至少 k 个不同用户才展示）。
- FR-58…FR-60 双向匹配：读者↔论文、论文→读者为 Must；研究者↔研究者为 Could，默认关闭，双方都选择加入才启用，须年满 18 岁，撤回后 ≤1 分钟停止展示、≤24 小时删除匹配资料（见 D-065）。
- FR-62…FR-65 支撑：LLM 只做离线或近线任务，不进滑动路径；从第一天记录曝光日志，算法模块自带离线基准；推荐模型升级须达到规模阈值（Could）；digest 邮件可一键反馈。

**前端交互**

- FR-66…FR-68 今日分拣：批次可选 15 / 25 / 35 张，看完不自动续发，"再来 10 篇"只作低强调链接；动作行 4 个按钮，撤销不限次；1:1 跟手、弹簧回弹，支持减弱动效。
- FR-69…FR-76、FR-86 卡片与其他界面：分拣卡 6 个核心字段（标题、AI 摘要、期刊·年份、评审状态、OA 状态、推荐理由），关键图只对 CC 许可论文展示；AI 内容一律标注、可全局关闭、不替代作者摘要；桌面键盘分拣；访客先看公开样本卡；中英双语；设计阶段交付可交互 [demo](demo/paper-feed-demo.html)；可安装的网页应用（PWA）离线可分拣。

**横切**

- FR-77…FR-83：邮箱与 OAuth 登录，注册时做年龄声明；两种部署同一代码，商用与地区开关控制受限来源与功能；部署级 API key 由出站网关（平台唯一对外出口）独占，用户级出版商凭证平台不可解密；每个可展示字段带权利标注，私有内容的派生物留在私域；数据可导出（BibTeX/RIS/JSON）、可删除；管理员控制台为 Should，对外只读 API 为 Could。

## 关键非功能需求

性能数值是设计目标，实现期压测校准；可用性、新鲜度、成本等 01 自拟的目标，由 V0 按实测校准后固化。

- 交互（NFR-9）：下一批卡片 p95 ≤300 ms；滑动提交到下一张可交互 ≤100 ms；交互到下次绘制（INP）p75 ≤200 ms；反馈后每用户模型 p95 ≤2 s 生效。
- 检索（NFR-10）：本地检索端到端 p95 ≤800 ms；单路召回 p95 超过 300 ms 即触发升级评估；联邦超时先返回本地结果，再流式补齐。
- 容量（NFR-11）：首档 T1 ≤1,000 活跃用户，按 1 万做容量设计；语料 ≤1,000 万篇，起步 100–300 万；日新增 1–3 万；无 GPU 硬依赖。
- 新鲜度（NFR-12）：arXiv 等按公告发布的来源在公告后 ≤6 h 进入用户的新论文收件箱；Crossref、Europe PMC 等增量来源 ≤24 h。
- 可用（NFR-13）：platform 核心读路径月可用性 ≥99.5%；DOI 元数据查找、最新论文收割、OA 定位、标题精确匹配四项关键能力至少两级替补；上游失败时卡片流、文献库与本地检索照常可用。
- 礼貌（NFR-14）：上游请求量不随用户数线性放大；重试 ≤3 次/请求且占比 ≤10%；arXiv 全平台每 3 秒 ≤1 次、单连接。
- 隐私（NFR-15）：阅读行为默认私有；私域派生物不进共享层；公开计数与社会证明须来自至少 `k_show` 个不同用户（初值 10，不得低于 5）；关闭个性化与删除标签即时生效。
- 成本（NFR-19）：platform 的 LLM、嵌入与计量 API 月成本 ≤US$300（不含算力与存储）；personal 默认零 LLM，启用第三方 LLM 时 ≤US$10/月；预算用到 80% 告警、100% 自动降级。

其余 11 条覆盖安全、可访问性（WCAG 2.2 AA）、国际化、可观测、离线可测、可维护、许可门禁、可移植、合规留存、幂等与可恢复。

## 非目标与红线

v1 的红线实质保留，"Web UI 与多用户为非目标"改为 v2 范围（见 D-041）。硬约束以 [08 合规安全隐私](08-compliance-security-privacy.md) 为准。

红线：

- 不绕过付费墙，不接盗版源；不破解验证码、不伪造指纹，遇挑战即停。
- 平台不代用户访问出版商；不预取、不池化、不共享用户凭证与订阅全文。
- 私域数据不以任何形式进入共享层，包括索引、嵌入、AI 摘要、特征与日志样本。
- 许可未知即不共享；图片许可未知即不展示。
- 每个上游只用一个平台身份，禁止多 key、多 IP、伪装 UA 与对同一主机的对冲请求。
- 只处理名录中登记的来源；dblp 不在线访问，SSRN 只取元数据与外链，知网、万方、维普零自动化，Google Scholar 只接受用户手动导出。
- 不提供公共全文上传；任何部署都不提供受限全文的批量下载。
- LLM 不进滑动路径；私有全文默认不发给第三方 LLM。
- 研究者匹配未经单独同意不展示个人资料，永不暴露阅读轨迹；不做面向儿童的功能。

非目标：

- 不做 AI 综述与问答主战场，深度检索集成开放服务。
- 不做无限流，分拣卡不显示社交计数；不做发布、私信、直播、积分等功能，不做广告与数据转售。
- 新增一级入口或卡片流常驻控件属于需求变更，须走评审或 ADR。
- 1 万用户以内不做生成式端到端推荐，不建在线训练集群；不引入独立图数据库，不维护 SQLite/PG 双后端。
- v2.0 不做原生移动端，不处理 OCR 扫描件。

## 成功指标

- 北极星：每周有价值阅读数 ÷ 周活跃用户数。有价值阅读指一周内按（用户, 作品）去重，发生过收藏、≥4 星评分、导出引用、打开全文之一；周活跃用户指当周有已登录会话且至少一次曝光。
- 不计：被撤回的事件、单次导出超过 5 篇、本人认领的作品、匿名会话。
- 另报每用户的中位数与四分位，以及不含"打开全文"的诊断口径 VR-strict。
- 打开全文只经每人每周的有价值阅读进入北极星，不单独计数、不按作品切片；用户侧取回的打开全文不进公共热度信号，也不进"收藏→阅读转化"等跨用户统计。北极星只以聚合形式展示。
- 学术场景没有公开参照值：首个里程碑只建基线，之后以"相对基线提升且护栏不劣化"验收。
- 护栏只防劣化：7 日与 30 日留存、不相关率与强负反馈率、"今日已看完"到达率、撤销与方向误判率、负反馈响应度（须为正）、默认强度下探索槽占比 10–20%、新作者曝光份额、单条有价值阅读耗时、会话时长与日活。

## 与 v1 的关系

v1 CLI 与 SQLite 进入维护冻结、只修缺陷，v2 提供一次性 ETL 迁移库与订阅（见 D-042），v1 的来源适配器经包装层复用。各需求落在哪个里程碑，见 [09 路线图](09-roadmap-and-milestones.md)。

## 怎么验收

- 本文在 V0 评审验收（AC-V0.4…AC-V0.9）：每条 FR 有描述、优先级、承接文档与验收项；四项需求各有场景和 ≥3 条 FR；编号不与 v1 重叠；共享术语已登记；北极星与护栏能用 06 的事件样本算出；v1 需求每节都有变更结论。
- 每条 FR/NFR 至少对应一个 AC-V<m>.<n>，V<m> 即所属里程碑。各需求落在哪个里程碑见 [09](09-roadmap-and-milestones.md)，逐条映射表在 09 的完整草稿里。
- demo 与可用性测试在 V0 验收（AC-V0.10）。
- 红线由数据流测试、出口审计与静态扫描验收（AC-0 系列）。

## 未决事项

- 默认假设待用户拍板：非商业、自托管或邀请制；不面向中国大陆公众运营；不购买付费数据档；robots 与文档化 API 冲突时保守处置（见 D-049）；双向匹配先做前两层；公开评论放在 V6；表示模型在 V1 分学科评测后定。
- 画像与场景待用户之声调研和 demo 可用性测试校准，建议在 V1 之前完成。
- 批次三档、"再来 10 篇"每日上限 60 与研究者匹配的 18 岁门槛都待验证。
- "社科"只含经济、金融、商业、管理，是否扩展到社会学、政治学、教育学待用户确认；地学、材料与中文生态待补充调研。
- T1 默认不配 GPU，画像摘要、LLM 重排等涉及画像的 LLM 功能关闭；是否配 GPU 待用户决定。
- k 匿名终值与差分隐私在 V6 开放公开计数前决策（见 D-064）。
