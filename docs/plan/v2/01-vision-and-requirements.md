# 01 · v2 愿景、用户场景与需求规格

> **定位**：v2 重新设计阶段的需求规格，回答"为谁、解决什么、做到什么程度、怎样算成功"。上游约束是[设计决策简报](00-design-brief.md)（以下简称"简报"），证据层是[调研综合](../../survey/00-survey-synthesis.md)（以下简称"综合"）与 14 篇调研（均于 2026-09-26 经对抗式核验）。本文不含实现代码，代码块均为**设计伪代码**。
> **本文定义**（简报 §9）：FR/NFR 编号（FR-17 起、NFR-9 起）、术语登记、成功指标；另给出用户画像（UP-xx）、用户场景（US-11 起）、非目标与红线汇总、对 v1 需求文档的变更清单、需求→设计文档映射。
> **本文不定义**：HC 全库编号与合规细则（08）、里程碑内容与 AC-V 最终编号（09）、API 面与部署拓扑（02）、DDL 与 RLS（05）、事件契约字段（06）。本文引用的 `HC-xx` 一律指 CP §3.1 的局部编号，08 统一登记时保留对照。
> **引用写法**（沿用 [survey README §4](../../survey/README.md)）：`MK §2.9` 指市场调研 §2.9，`MK I-4` 指其第 4 条启示，`SM §3-4` 指社媒调研 §3 第 4 条，`SI-xx` 指综合 §6.1 的设计输入，`G1–G7` 指 MK §2.9 的能力空白，`G-01…G-16` 指综合 §7.3 的调研缺口。链接只指向文件，节号写在文字里。
> **默认假设**：简报 §8 的 Q1–Q7 尚待用户拍板，依赖其默认值的条目标注"（默认假设 Qn）"。
> **标记**：`⚠` 表示调研中未核验或待验证的事实（照录调研原标注，不升级可信度）；"设计目标（草案）"表示本文提出、待实现期压测或实验校准的目标值，不是事实断言。

## 0. 结论速览

1. **产品**：面向跨学科研究者的论文发现平台。从合法来源持续收割论文，以可解释的个性化推荐把"今天值得看的论文"做成一叠有限的卡片，用户靠滑动分拣；用户自己的机构权限只用于本人取回全文（简报 §2）。差异化来自五项能力的**组合**，外加经管工作论文的新鲜度与多用户私域合规，而不是任何单项能力（MK §2.5 续核验修正、MK I-1）。
2. **用户**：定义 11 类画像（UP-01…UP-11），覆盖 CS/AI、经济、金融、管理、数学与理论物理、化学/材料、生物医学、心理学、跨学科研究者，以及实验室管理员（部署方）与 v1 个人用户（§4）。画像是基于调研证据的假设，须经 G-01 用户之声调研与 demo 可用性测试校准。
3. **场景与原话承接**：§2.5 把用户需求 1–5 的 26 个要点逐条写成"用户看到什么 → 承接条目 → 与字面理解的差别"（例如"点赞"在界面上叫"想读"，"留言"在 v2.0 是私人笔记、公开评论在 V6）。US-11…US-42 共 32 个场景，按 §5.0 的 19 类覆盖清单核对，涵盖需求 R1–R4、部署运维与 v1 迁移（§5）。
4. **功能需求**：FR-17…FR-87 共 71 条，按需求 R1–R4 与横切组 RX 分组；Must 48 条、Should 15 条、Could 8 条（§6）。FR-84…FR-86 与 NFR-27 是吸收 05、06、07 需求候选后追加的条目，FR-87 按简报 R2-48 追加，§6.6 给出 02–08 需求候选的登记对照。
5. **非功能需求**：NFR-9…NFR-27 共 19 条，含简报性能预算、容量档、新鲜度、降级、礼貌、隐私、安全、WCAG 2.2 AA、中英双语、成本、可观测、离线可测、许可门禁、可审计与可恢复（§7）。
6. **成功指标**：北极星为"每周每个活跃用户的有价值阅读数"，本文给出可计算的定义与排除规则（§9.1）；时长与日活只作护栏。
7. **红线**：保留 v1 五条红线的实质，第 6 条（Web UI/多用户为非目标）改为 v2 范围，第 3 条（不再分发）细化为 P-02/P-03；新增平台级红线 12 条（§8）。
8. **v1 关系**：v1 CLI 与 SQLite 进入维护冻结，00-requirements 逐节变更见 §13.2；除简报 §7 的 13 项 ADR 候选外，本文建议增补两项："v1 ADR 在 v2 中的适用范围"总则 ADR，以及身份模型与 D-007 关系的 ADR（§13.5）。
9. **术语**：登记简报 §5 全部术语与本文新增术语；给出 10 组编号/术语歧义的消解规则，其中"Channel"两义、"V0–V4 展示级 / V0–V7 里程碑"与"非个性化模式取值"三组已由简报 §10 的 R2-02、R2-03、R2-05 裁定（SourceChannel/频道、DL0–DL4、`np_time`/`np_source`），k 参数按 R2-04 统一为 `k_cf`/`k_reason`/`k_show`（§14.4）。
10. **异议**：无推翻简报裁决的异议；首轮提出的 13 项细化中，9 项已由简报 §10 第 2 轮裁决采纳或关闭（检索 p95 两个口径 R2-39、personal 部署 OA 批量 R2-48、资格集合曝光下限 R2-41、批次宁短勿滥 R2-42、证据过期宽限 R2-16、社科范围 R2-25、术语 R2-02/03/05、北极星 VR-strict R2-44、`host_is_user_device` R2-28），其余见 §16。
11. **界面极简是可验收的约束**：一级入口 3 个（今日 / 收藏 / 我，简报 R2-49）、Deck 动作行 4 个按钮、顶栏 3 项，新增一级入口或常驻控件须走需求变更（FR-66、FR-67、§8.3）。

### 2.4 外部环境变化（2025–2026）

调研期间观察到的上游变化，直接决定了"先收割、后联邦"（P-01）与"策略引擎是一等公民"（简报 §6.1-5）两条原则：

- **限速与计费收紧**：Crossref 按请求类型分池，公共池列表查询 1 次/秒、并发 1；OpenAlex 改为按美元计费，免费 key 每日 $1，公共快照改为季度更新；arXiv 全平台合计每 3 秒 1 次、单连接，2026-02 起 429 频发；S2 的 key 只有 1 RPS（综合 §0-4；AG §0-1、§0-3；CS §0-2）。
- **robots 与条款漂移**：dblp 三个主机 robots 改为全禁；SSRN 宣布 2026-12-31 前关停商业线，其 ToU 禁止任何自动化查询；PMC 下线 OA Web Service，只剩 4 条自动化通道；bioRxiv/medRxiv 启用新前缀 10.64898（综合 §0-5；CS §0-1；SS 摘要 §1；LS §0-3）。
- **产品关停**：Papers with Code 于 2025-07 无预告下线；与 v2 形态最接近的移动论文 feed Researcher App 于 2024-11 月底关停，只提示用户自行备份（MK §2.2.I）。这要求 v2 把"数据可导出、不锁定单一上游"写成约束（SI-66、MK I-16）。

## 3. 产品定义与定位

### 3.1 一句话与价值主张

> 面向研究者的跨学科论文发现平台。它从合法来源持续收割论文，用可解释的个性化推荐把"今天值得看的论文"做成一叠卡片，用户靠滑动分拣。用户自己的机构权限只用于本人取回全文。（简报 §2）

- **五项能力的组合**：跨学科（尤其包含经管金融工作论文）、卡片分拣交互、学习型个性化、可解释推荐、用户自带权限取全文。MK §2.5 的竞品矩阵中没有任何产品五列同时具备（综合 §0-11）。
- **不宣称"唯一"**：单项能力均已有先例——机构登录取全文有 R Discovery（GetFTR + LibKey）、Read by QxMD、Google Scholar；"滑动 + 自称学习"有 ZiNote；SSRN/NBER 元数据已被 OpenAlex 与 S2 收录（MK §0-1、I-1 续核验修正）。价值主张只能写成"组合 + 经管 WP 新鲜度 + 多用户私域合规"。
- **不做**（简报 §2）：AI 综述与问答主战场（集成开放服务即可，MK I-15）；社交网络化的时长竞争；任何形式的全文再分发。
- **形态演进**：实验室或团队自托管多用户 → 邀请制托管 → 机构版（SSO、link resolver、席位；平台不代理机构访问）（MK §2.9，与 B-02 一致）。

AC-0.1…AC-0.5 在 v2 继续适用；AC-0.5 中"各 adapter 默认限速"的对象扩展为"各 connector 与全局调度器"。

### 8.2 v2 新增的平台级红线

以 08 统一登记的 HC 为最终口径，此处只汇总需求层面必须遵守的 12 条：

1. 平台服务器不以平台出口代用户访问出版商，不持有可用的出版商会话（P-03；HC-03）。
2. 不预取、不池化、不共享任何用户凭证与订阅全文；不暴露"他人已取回/有访问权"的信号（HC-02、HC-04）。
3. 私域到共享层的任何数据路径都禁止，包括索引、嵌入、TL;DR、特征、分享卡与日志样本（HC-01）。
4. 许可未知即不可共享；图片许可未知即不展示（HC-05、HC-09）。
5. 对每个上游只用一个平台身份；禁止多 key、多 IP、住宅代理、UA 伪装与对同一第三方主机的对冲请求（HC-10）。
6. arXiv 全平台合计每 3 秒 ≤1 次、单连接；不存储、不提供 arXiv e-print（CC 许可允许的除外）（HC-06）。
7. 平台层不接 IEEE API；不对 ACS 做任何自动化；不自动访问 ACM DL 网站；三者元数据经 Crossref 获取（HC-27）。
8. 不在线访问 dblp 站点（改用 DROPS 快照或 SPARQL）；SSRN 只取元数据与外链；知网、万方、维普零自动化（简报 §7-3、§7-4；SI-19）。
9. LLM 不进滑动热路径；AI 内容一律标识；共享 AI 内容只由可共享来源派生；私有全文默认不发送给第三方 LLM API（P-07；HC-11）。
10. 不提供公共全文上传或转存；评论不得附 PDF 或全文（HC-16）。
11. 研究者↔研究者匹配默认关闭；未经单独同意不向他人展示任何个人资料；永不暴露阅读轨迹（HC-18）。
12. 不做面向儿童的功能，设最低年龄（HC-19）。

### 8.3 产品与技术非目标

- 不做 AI 综述与问答主战场，深度检索通过集成开放服务提供（简报 §2；MK I-15）。
- 不以时长或日活为优化目标；不做无限流；分拣卡不显示社交计数（简报 §2；SM §3-4）。
- 不做发布、私信、直播、积分、测验等社交或游戏化功能（UX §2.9.1）；产品命名不用"TikTok"（UX §2.2.4）。
- 界面上刻意不做：双击点赞、付费撤销、自动播放与轮播、论文短视频与 AI 播客、首屏强制登录与多页长引导、v2.0 的分享海报、四向二维手势编码、Deck 上的"今天多探索"等快捷调节（07 §2.2 X5、X7、X8、X14、X15、X17，§23 Q-FE-15）。完整清单与重评条件以 07 §2.2（X1–X19）为准。
- 界面预算是需求层约束：一级入口 ≤3 个，Deck 动作行 4 个按钮，Deck 顶栏 3 项（FR-66、FR-67）。新增一级入口或 Deck 常驻控件属于需求变更，按 §10.3 降回 review 或走 ADR。
- 不做广告、付费推广与数据转售（MK §2.10）。
- 1 万用户以内不做生成式端到端推荐，不建在线训练集群（简报 §6.4-2）。
- 不引入独立图数据库；不维护 SQLite/PG 双后端（简报 §6.2-4；B-01）。
- v2.0 不做原生移动端（Expo 延后到 v2.x，B-05）；不提供公开评论与公开评分（V6，默认假设 Q6）。
- 默认不面向中国大陆公众公开运营（默认假设 Q2）。
- 不提供受限（auth-gated）全文的批量下载，任何部署都不提供（HC-32）；唯一例外是 personal 部署可批量取回许可允许的 OA 全文到本人私有空间（FR-87，Could，简报 R2-48）；v1 CLI 在维护冻结期继续可用（§16-4）。

## 9. 成功指标

### 9.1 北极星：每周每个活跃用户的有价值阅读数

北极星沿用简报 §2 的四项行为，并由本文补齐可计算的口径（简报 §9：成功指标由 01 定义）：

| 要素 | 定义 |
|---|---|
| 统计周期 | ISO 周（周一起），按用户时区切分；全站周报按周编号汇总（与 06 §3.1 一致） |
| 结算 | 各用户的周在其结束后 24 h 结算（设计值）；结算前发生的撤回（含跨周撤回）一律生效；结算后的撤回不改写已发布的周报，但本人模型照常回滚（06 §5.5）。全站周报在所有时区都过结算时刻后生成，保证可复现 |
| 周活跃用户（WAU） | 当周至少有一次已登录会话、且产生过 ≥1 条 impression 的用户；surface 为 digest 的曝光，只有该期 digest 被打开（`digest_open`）才计入活跃判定；排除服务账号与 API/MCP 调用 |
| 有价值阅读（VR） | 当周内按 (user, Work) 去重计数，满足下列事件至少一项：`save`（收藏）；`rate` ≥4 星（以该周内对该 Work 的最后一次评分为准，清除评分视为无评分）；`export_citation`（导出引用、复制 BibTeX、发送到 Zotero；批量导出按其中每个 Work 分别计）；`open_fulltext`（打开 OA 链接或出版社外链，或用户侧取回成功；取回失败不计） |
| 排除规则 | 被 `undo` 或 `unsave` 撤回的事件不计；单次导出超过 5 篇视为文献库管理动作，不计入 `export_citation`（与 06 §3.1 一致；依据 SM §4-2"导出可能被批量导出污染"）；用户已认领为本人作品的 Work 不计（06 已采纳，06 AL-7）；匿名样本会话不计。以上三项排除由简报 R2-44 确认 |
| 事件字段依赖 | 已由 06 §5.3–§5.4 定义（06 AL-8）：出版社外链记为 `open_fulltext{route: user_side, via: publisher_link}` 且不带 `success`；批量导出带 `work_ids[]`（信封 `work_id` 为空），可带 `impression_ids[]`（简报 R2-47）；digest 条目的 serve 记录以 `batch_id` = `digest_id` 关联，`digest_open` 带 `digest_id` |
| 主口径与分布 | 主口径保留简报的四项口径：VR 总数 ÷ WAU；同时报告每用户 VR 的中位数与 P25/P75，防止少数重度用户拉高均值；并报告 06 §3.1 的三个诊断口径：VR-strict（不含 `open_fulltext`，简报 R2-44 设为诊断口径）、VR_rec（只计 Deck、探索、digest 三个面）与新增 VR（历史上首次） |
| 隐私约束 | `open_fulltext` 只进入本人模型与北极星统计，不进入任何公共热度信号，以免暴露"有人拥有访问权"（简报 §2；HC-02）；北极星只以聚合形式展示 |
| 目标值 | 学术场景没有公开的参照值（SM §4-1；G-08），首个里程碑只建立基线；此后以"相对基线提升且护栏不劣化"为验收方式 |

```python
# 设计伪代码（非实现）：周北极星计算。事件名与字段以 06 §5 的事件契约为准。
# 辅助函数：cluster_of(work_id) 取 Work 的 cluster_id；works_of(e) 对单篇事件返回 [e.work_id]，
# 对批量导出返回 e.payload["work_ids"]；digest_of(e) 取 digest 曝光所属 serve 记录的 batch_id（= digest_id；字段见 06 §5.3–§5.4）；
# is_service_account(uid) 判定服务账号；median、quantiles 同 Python statistics 模块。
from collections import Counter

VALUABLE = {"save", "rate", "export_citation", "open_fulltext"}
RETRACTING = {"undo", "unsave"}

def weekly_north_star(events, week, claimed_works, settle_at, export_cap=5):
    known = [e for e in events if e.server_ts <= settle_at]            # 截至结算时刻的全部事件
    retracted = {e.retracts_event_id for e in known if e.type in RETRACTING}   # 跨周撤回同样生效
    wk = [e for e in known if e.iso_week_user_tz == week                # ISO 周，按用户时区
          and e.user_id is not None and not is_service_account(e.user_id)]   # 匿名样本会话无 user_id
    opened = {e.payload["digest_id"] for e in wk if e.type == "digest_open"}
    wau = {e.user_id for e in wk if e.type == "impression"
           and (e.surface != "digest" or digest_of(e) in opened)}         # 未打开的 digest 不算活跃
    last_stars = {}                                                       # 同一 (user, Work) 取周内最后一次评分
    for e in sorted((x for x in wk if x.type == "rate" and x.event_id not in retracted),
                    key=lambda x: x.occurred_at):
        last_stars[(e.user_id, cluster_of(e.work_id))] = e.payload.get("stars")   # 清除评分为 None
    reads, reads_strict = set(), set()
    for e in wk:
        if e.event_id in retracted or e.user_id not in wau or e.type not in VALUABLE:
            continue
        if e.type == "export_citation" and e.payload["batch_size"] > export_cap:   # 06 §5.3 #17
            continue                                                      # 文献库管理动作，不计
        if e.type == "open_fulltext" and e.payload.get("success") is False:
            continue                                                      # 用户侧取回失败不计
        for work in {cluster_of(w) for w in works_of(e)}:                 # 按 Work（cluster_id）去重
            key = (e.user_id, work)
            if key in claimed_works:                                      # 本人已认领的作品不计
                continue
            if e.type == "rate" and (last_stars.get(key) or 0) < 4:
                continue
            reads.add(key)
            if e.type != "open_fulltext":
                reads_strict.add(key)                                     # VR-strict：不含打开全文
    per_user = Counter(u for (u, _) in reads)
    dist = [per_user.get(u, 0) for u in wau]
    n = max(len(wau), 1)
    return {"vr_per_wau": len(reads) / n,
            "median": median(dist) if dist else 0,
            "p25_p75": quantiles(dist, n=4)[0::2] if len(dist) > 1 else None,
            "vr_strict_per_wau": len(reads_strict) / n}
```

## 16. 异议与备选

本文**没有推翻简报任何裁决的异议**。以下 13 项是细化、口径澄清或需主 agent 确认的备选，均附证据（第 9–13 项为第 1 轮评审新增）；各项末尾的"状态"按简报 §10 第 2 轮裁决更新（一致性审计 2026-09-27）：

1. **术语与编号歧义**（§14.4）。简报 §5 用"Channel"同时指 SourceSpec v2 的三个通道与用户频道；里程碑 V0–V7 与 CP 展示级别 V0–V4 直接冲突（例如"V1"既可指里程碑，也可指"只显示标识与链接"的展示级，CP §2.2.4）。建议采纳 §14.4 的限定词规则，并请 08 为展示级别设别名。这是对简报 §5 的补充，不改变其定义。 **状态**：已由简报 R2-02、R2-03 裁定（SourceChannel/频道；展示级别 DL0–DL4）。
2. **北极星中 `open_fulltext` 的测量偏差**。platform 部署的默认动作是"在出版社打开"外链（P-03），外链点击不等于阅读，平台也观测不到后续行为；全部计入可能被"点开即走"抬高。SM §4-2 也指出"收藏不等于阅读、阅读也不等于引用"。建议：主口径保持简报的四项行为，同时固定报告不含 `open_fulltext` 的 VR-strict 口径（§9.1；06 §3.1 与其 §24 的 A4 已采纳同一做法）；06 可为 `open_fulltext` 增加最小信号（如回到应用后的标记）。 **状态**：已由简报 R2-44 裁定：主口径保留四项，VR-strict 作诊断；排除本人认领作品、单次批量导出 >5 篇与匿名会话。
3. **检索 p95 的两个口径**。简报 §3 定本地检索 p95 ≤800 ms，RT §11 把"检索 p95 >300 ms"列为 T1 升级触发条件。本文的解释是：800 ms 为端到端口径（含解析、融合、重排与装配），300 ms 为索引层单次召回口径；NFR-10 同时采用两者。请 04 确认。 **状态**：已由简报 R2-39 裁定：800 ms 为端到端本地检索 p95，300 ms 为单路召回的升级触发（NFR-10 已改）。
4. **personal 部署失去 v1 的批量取回能力**。P-03 规定受限全文"只在用户显式触发时单篇取回"，对 personal 部署同样适用，因此 v1 的 US-1、US-2、US-7（按日配额批量 `pull`）在 v2 没有对应。支持这条裁决的证据：出版商与机构对系统性下载有明确限制（Cambridge 每小时超过 500 个 PDF 可撤销访问、WSP 短时间 200 次下载即切断（二手来源，◐），NS 摘要 §10；EZproxy 的账号共享判定规则，CP §0-4）。08 §17.1 的 AC-0.18 已把"任何部署都没有批量取回 auth-gated 全文的入口"列为红线，与这条裁决一致。备选：(a) 维持裁决（推荐），批量需求在冻结期由 v1 CLI 承接；(b) 为 personal 部署增设一条 Could 级需求"许可与 ToS 允许的 OA 全文批量取回到本人私有空间，沿用 v1 限速与日上限"，受限全文仍单篇。请主 agent 与用户裁定。 **状态**：已由简报 R2-48 裁定采纳备选 (b)，登记为 FR-87（Could，只限许可允许的 OA 全文）；受限全文仍单篇。
5. **查询意图的数量**。简报 §6.2-1 规定四意图，RT §3.5.1、§4.3.1 与 SI-24 另列 EXPAND（引文扩展）。本文以 FR-43（Should）要求该能力，但不把它定为意图；是否独立成意图由 04 决定。 **状态**：仍待主 agent 裁定：04 §19-13 提议把 EXPAND 列为第五意图（04 §20 第 26 项），简报 §10 未涉及。
6. **身份模型与 D-007**（§13.5 第 2 条）。三层身份把预印本与正式版视为同一 Work 的不同 Version，与 D-007"默认不合并、以 `preprint_of` 互联"的表述需要对齐；若语义改变，须立 ADR 点名 D-007。 **状态**：仍待 09 起草 ADR（03 §19 第 2 条给出同一建议）。
