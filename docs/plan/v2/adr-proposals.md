# v2 ADR 草案（proposed）

> **定位**：v2 重新设计阶段需要以 ADR 记录的架构决策草案，按 [decision-log](../decision-log.md) 的格式起草，编号 D-040…D-071，**全部为 proposed**。它们经用户逐条裁决后，由主 agent 以 accepted 追加进 decision-log，并在被修订或取代的 v1 条目上标注 revised-by / superseded-by（[09 路线图](09-roadmap-and-milestones.md) V0-T1）。本文件不修改 decision-log。
> **依据**：[设计决策简报](00-design-brief.md) §7（13 项 ADR 候选）与 §10 第 2 轮裁决（R2-01…R2-50，其中 R2-01、R2-08、R2-41 明确要求起草 ADR）；各设计文档提出的 ADR 候选（01 §13.5、02 §6.4、03 §14.3 与 §19、04 §18.2、05 §14.3、06 §23.3、08 §13）；[调研综合](../../survey/00-survey-synthesis.md)与 14 篇调研（2026-09-26 核验）。
> **写法**：每条含状态·日期·依据、与旧决策的关系、背景、决策、理由、影响。"⚠"照录上游的未核验标注。数值目标均为设计目标（草案），以承接文档与实现期压测为准。

## D-040 v1 ADR 在 v2 中的适用范围（总则）

- 状态：proposed · 日期：2026-09-27 · 依据：[AGENTS.md](../../../AGENTS.md)"取代架构决策须由新 ADR 点名旧 ADR"；[01](01-vision-and-requirements.md) §13.1、§13.5-1；简报 B-03
- **与旧决策的关系**：不 supersede 任何单条 ADR；本条是 D-001…D-039 在 v2 中效力的总索引，逐条指向修订或取代它们的 D-041 起的 ADR。
- **背景**：v2 把单用户 CLI 改为多用户平台加 personal 部署，简报 §6 的多项裁决实质改写了 v1 的架构决策，其中 D-004（六阶段 pipeline）被简报 §6.1-6 改写却不在简报 §7 的清单中（01 §16-7）。如果不逐条声明，实现者无法判断某条 v1 ADR 在 v2 中是否仍然约束自己。
- **决策**：
  1. D-001…D-039 继续约束 v1 实现（维护冻结期，只修缺陷）。
  2. v2 只受 D-040 起的 ADR，以及下表明确列为"继承"的 v1 ADR 约束；表中未列为继承的 v1 ADR 对 v2 无约束力。
  3. v2 实现若需依赖一条未列为继承的 v1 决策，须先起草新 ADR（D-072 起）。

## D-041 需求范围修订：Web UI 与多用户进入 v2，"不再分发"细化为数据三域与用户侧取回

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §1、§2、§7-1、P-02、P-03；[01](01-vision-and-requirements.md) §8、§13.2；[08](08-compliance-security-privacy.md) §17.1
- **与旧决策的关系**：revises [00-requirements](../../archive-v1.md#docs-design-00-requirements-md) §5 第 6 条（Web UI、多用户/团队协作为非目标）；§5 第 3 条（不再分发）的实质保留并细化；§5 第 1、2、4、5 条保留。
- **背景**：用户的五项需求中，前端卡片交互（R4）、多用户数据库与每人偏好（R2）、推荐与双向匹配（R3）都以 Web 界面与多用户为前提，与 v1 的第 6 条非目标直接冲突。07 在本条生效前不能进入 approved（07 §21）。
- **决策**：
  1. Web UI（PWA）与多用户（platform 部署）改为 v2 范围；personal 部署继续提供单租户形态。OCR 扫描件仍为非目标。
  2. 第 3 条"不提供把下载内容公开、共享或批量导出给第三方的功能"的实质保留，并细化为：共享层只放公开元数据与许可允许再分发的内容及其派生物（P-02、HC-05）；auth-gated 全文及其派生物只在本人私域，不跨用户去重，不提供公共全文上传（HC-01、HC-02、HC-16）；受限全文只在用户侧单篇取回（D-053）。
  3. 新增 01 §8.2 的 12 条平台级红线，验收以 AC-0.6…AC-0.18 为准（09 §4.1）。
  4. 以下仍为非目标：AI 综述与问答主战场、以时长或日活为优化目标、发布/私信/直播/积分等社交与游戏化功能、广告与数据转售、受限全文的批量下载（任何部署）。
- **理由**：不改第 6 条，v2 的核心需求无法成立；只改第 6 条而不细化第 3 条，平台化会让"本人、本地、个人科研"的许可前提失效（CP §2.0）。
- **影响**：00-requirements 顶部加一行指向 01（approved 后）；01 §13.2 的逐节变更成为正式变更；07 可进入 approved；acceptance-criteria 增补 v2 区。

## D-042 v2 单栈 PostgreSQL 18、v1 维护冻结与一次性 ETL

- 状态：proposed · 日期：2026-09-27 · 依据：简报 B-01…B-03、B-05、§6.3-6、§7-5；[05](05-data-platform.md) §10、§14.3-2；[02](02-architecture.md) §2.6、§6.5；RT §10.7
- **与旧决策的关系**：revises D-001 中"存储初期 SQLite、预留升级 PostgreSQL 的迁移路径"（在 v2 中改为单栈 PG）；D-017 决策 3 的"SQL 方言中性"原则不适用于 v2；D-025、D-032 只适用于 v1、personal 部署与 pc-agent。
- **背景**：v2 需要 RLS、分区、pgvector、BM25 扩展与 PG 原生队列；维护 SQLite 与 PG 双后端会让每个查询与迁移都有两份实现。v1 本地库只有 179 篇论文、228 个标识符与 2 个订阅（05 §10.2），迁移成本极低。
- **决策**：
  1. v2 服务端只支持 PostgreSQL 18（pgvector；BM25 扩展按 D-060），不维护双后端；platform 与 personal 使用同一服务镜像（简报 B-02）。
  2. 后端栈：Python 3.12+、FastAPI、Pydantic v2、psycopg 3（许可按 D-044）、procrastinate 为首选 PG 原生队列、pgqueuer 为备选（D-069）。
  3. v1 CLI 与 SQLite 实现进入维护冻结：打 tag `v1-final`，只修缺陷，持续可用；v1 adapter 经 `v1_bridge` 复用、不重写（D-046）。
  4. 提供 v1→v2 一次性 ETL：以 `mode=ro` 读取 v1 库（前置 `schema_version = 7`），COPY 写入 v2；派生结构（BM25、向量、`cluster_id`、`route_stat`）在 PG 侧重建、不搬运；**权利从严**（无法证明为 A 或 B 类的摘要不进 `corpus`，ETL-R1…R5）；**不晋升**（v1 的私有物永不进入共享层，PDF 与抽取全文只在 personal 且 `host_is_user_device=true` 时进入本机私有空间）；经 `ops.etl_v1_map` 保证重跑幂等；v1 凭证不迁往任何服务端。
- **理由**：单栈把复杂度集中在一个成熟数据库；ETL 只读、幂等、可重跑，任何一步都能丢弃重来，v1 始终可用。
- **影响**：09 §6 的迁移步骤 M0…M8；AC-V3.29（ETL-V1…V10）；D-034 的 FTS5 在 v2 由 D-060 替换；v1 的 `crawler search` 随 v1 冻结。

## D-043 数据四域、单向流、派生继承最严与共享索引资格

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-02、§7-6、R2-19、R2-21、R2-24；[05](05-data-platform.md) §2、§14.3-1；[08](08-compliance-security-privacy.md) §3.2–§3.7；[04](04-retrieval-and-routing.md) §9.1、§18.2-5；[03](03-sources-and-corpus-pipeline.md) §8.4
- **与旧决策的关系**：新增（v1 单用户，无对应 ADR）；细化 D-041 第 2 条。
- **背景**：平台化后，平台是运营者与被许可方；任何从私有数据到共享层的路径（索引、嵌入、TL;DR、特征、解释、日志样本）都会把个人或受限内容暴露给他人（HC-01、HC-02）。B 类摘要（出版方版权、公开分发）是否可作共享派生的输入，在法务意见（LQ-02、LQ-05）之前没有结论。
- **决策**：
  1. **四域**：`corpus`（共享只读，只放公开元数据与许可允许再分发的内容及其派生物，只经 ingest 角色写入）、`usr`（全表 RLS，放偏好、反馈、凭证密文、私有全文及其一切派生物）、`evt`（只追加、按月分区；用户活动派生的共享统计只在 `evt.agg_*`，经聚合闸）、`ops`（队列、健康、配额账本、策略快照、审计）。
  2. **单向流不变式**：没有任何角色同时"可读 `usr`"与"可写 `corpus`"；私有派生只写 `usr`；聚合只在 `evt.agg_*` 且满足 D-064 的 k 门槛；应用角色不是表 owner、无 BYPASSRLS，用户上下文用 `SET LOCAL`（05 INV-D1…D8）。
  3. **字段级权利标注**：每个可展示字段带 `display_scope ∈ {public_shared, per_user_only, link_only}`、权利类别、`license_code`（SPDX 或 `x-` 规范码）与署名文本；展示层只按这些字段决定；展示级别写作 DL0–DL4（简报 R2-03）。
  4. **派生继承最严**：由 per_user 内容派生的一切一律 per_user，不得进入共享索引、全局模型、协同信号或他人可见的解释；性质要求单调、吸收、不可混合（08 §3.6）。
  5. **共享索引资格**：C 类摘要（出版商 API 个人用途）永不进入共享层；B 类摘要默认纳入内部词法索引与嵌入，但不展示（展示上限 DL3，跨用户只显示有长度上限的摘录与链接），不作为任何 `public_shared` 派生物（TL;DR、翻译）的输入；以 `policy.index_b_abstracts` 开关与 `input_rights_max` 支持可逆的定向重建，LQ-02 结论为否时关闭并重建（R2-21）；声明了机器可读 TDM 保留的出版方，其 B 类摘要不纳入。声明自然语言保留者是否也排除，建议从严排除（01 审计 C-4，待用户确认）。
  6. **兴趣并集**：平台收割的兴趣并集只存键与计数；由私有文献库派生的细粒度键（引文邻域、作者）须至少 `k_cf` 个不同用户共有才并入平台收割，否则只做该用户的按需查询（R2-19）。
- **理由**：把隐私与许可做成结构约束（角色、触发器、数据流测试），比依靠每段代码的纪律可靠；B 类摘要进入内部索引能显著提升检索召回，而不展示、可逆重建把法律风险限制在可回退范围内。
- **影响**：05 的 DDL、RLS 与聚合闸；03 的 enrich 输入闸；04 §9.1 的索引资格；AC-0.6、AC-0.15、AC-V2.20、AC-V3.7、AC-V3.11、AC-V4.25。

## D-044 依赖、模型与数据的许可门禁四级

- 状态：proposed · 日期：2026-09-27 · 依据：简报 B-06、R2-01、R2-22；[08](08-compliance-security-privacy.md) §10.6、§14-6；[02](02-architecture.md) §2.10、§8-1；综合 §4.4
- **与旧决策的关系**：revises 简报 B-06 的字面白名单（"只用 Apache/MIT/BSD/PostgreSQL 许可"）；D-017 决策 3（依赖最小化）的精神继承。
- **背景**：B-06 按字面执行会否决简报自己选定的 psycopg 3（PyPI 元数据为 `LGPL-3.0-only`，08 §10.6 于 2026-09-27 读取），也会把 Python 运行时（PSF）、ISC、Zlib 等宽松许可与 OFL 字体挡在门外；同时 NC 数据（MSC2020 为 CC BY-NC-SA 4.0，NS §3-11）需要明确默认状态。
- **决策**：核心链路的依赖、模型与数据按四级门禁管理（08 §10.6）：
  1. **放行**：Apache-2.0、MIT、BSD-2/3-Clause、ISC、PostgreSQL、PSF-2.0、Blue Oak Model License 1.0.0、Unlicense、CC0、Zlib；字体 SIL OFL-1.1（未修改、作静态资源分发）；数据 CC0、PDDL、CC BY、ODC-BY（仅数据库权）；Apache-2.0 或 MIT 的模型权重。登记即可。
  2. **评审**：LGPL-2.1/3.0、MPL-2.0、EPL-2.0 在"不修改、以库形式动态导入"时评审后放行——**保留 psycopg 3**；数据 CC BY-SA、ODbL 与带地域或用途限制的模型许可评审后放行（如 zbMATH Open 数据、HY-MT）。评审记录写入许可登记表（⚠ LGPL 的义务以法务意见为准）。
  3. **可选**：AGPL、SSPL、BUSL 软件与 NC、NC-SA、NC-ND 数据和模型只作可插拔可选项、默认关闭；非商业部署可由运营者显式开启，`platform.commercial=true` 时强制关闭（D-045）。其中 **MSC2020 作可选插件，任何部署（含非商业）默认不加载**，数学主题叶子用 arXiv 数学分类与 OpenAlex Topics（R2-22）；Scholar Inbox 评分数据集只用于非商业离线研究。
  4. **禁止**：没有 LICENSE 的仓库（只借思路、不复制代码）、来源不明的代码、许可不明的数据与权重、来自盗版源的数据；SPECTER2 proximity adapter 在许可核清前按禁止级处理（⚠）。
  门禁作用于运行时核心链路（含容器系统包与前端打包产物）；开发与测试工具单独登记；AGPL 工具不得以网络服务形式向用户提供。CI 每次构建产出 SBOM，核心链路出现可选级或禁止级即失败。
- **理由**：四级比字面白名单更贴近真实义务：宽松许可族义务相当，弱 copyleft 在动态使用时一般不传染调用方，而 NC/AGPL 类必须隔离以保留商用选项（简报 Q1 的最严口径）。
- **影响**：02 §2.10 的白名单与黑名单；04 §1.6、07 §15.1 的选型；AC-V0.13；MinIO 因 AGPL 与停止维护不选（D-070）；ParadeDB（AGPL）、Grafana（AGPL）只作可选。

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §5、§6.1-1、§6.1-4、§6.1-7、R2-02、R2-10、R2-11、R2-12、R2-17、R2-23；[03](03-sources-and-corpus-pipeline.md) §2–§5、§13、§14.3、§19-3；[支持名录](../../catalog/source-directory.md) §2、§8、§10.3

## D-047 语料流水线六段（在 v2 中取代 D-004）

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-01、§6.1-2、§6.1-6、R2-13、R2-34、R2-35；[03](03-sources-and-corpus-pipeline.md) §10；[02](02-architecture.md) §2.3.6–§2.3.10、§2.9；[04](04-retrieval-and-routing.md) §11、§12
- **与旧决策的关系**：在 v2 中 supersedes D-004（discover → enumerate → resolve → fetch → extract → ingest）；D-005 的"元数据主干走聚合 API"原则继承；D-039 中"backfill 命令"的需求由 bulk 快照导入取代。
- **背景**：v1 的六阶段以"清单先行、下载置后"服务本人批量下载；v2 的产物是共享的本地语料与每个用户的 FeedInbox，而受限全文只能在用户侧单篇取回（D-053），后台流水线不再下载受限全文。
- **决策**：
  1. 语料流水线固定为 **harvest → normalize → identify → enrich → index → percolate** 六段，各段幂等、以持久化任务为边界、可断点重跑。

  4. **本地底座与增量**：OpenAlex 季度快照等 `bulk_snapshot` 按全体用户兴趣并集导入子集（D-043 第 6 条）；期刊与带 DOI 的 WP 以 Crossref 为主干，最新论文以 `from-created-date` 加重叠窗口为主、`from-index-date` 只补漏并按标识符去重；生命科学以 Europe PMC + PMC 允许通道 + Crossref 为主干，PubMed 在 NCBI 书面确认后启用（R2-13，D-049）；预印本走原生通道（bioRxiv、medRxiv、PsyArXiv 以 Crossref 为首选）。
  5. **职责划分**：WatchKey 的编译与新鲜度调度算法由 04 定义，由 Harvest Scheduler 执行，connector 消费（R2-34）；Percolator 的输入包括新 Work，以及新增 Version 或匹配字段变更的已有 Work（R2-35）；段间经事务性 outbox 发布 `corpus.change`（D-069）。
- **理由**：P-01"先收割、后联邦"让卡片流、LATEST 与频道只读本地；把全文 fetch 移出后台是 HC-03 的直接要求。
- **影响**：03 §10、02 的组件划分；AC-V1.22…V1.25、AC-V2.38…V2.45；v1 的 `pull`、`backfill` 语义在 v2 中不存在（US-1、US-2、US-7 的去向见 01 §13.4）。

## D-048 身份模型三层与版本边投票（修订 D-007 的表示）

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §5（Work/Version/Manifestation）、§6.1-6；[03](03-sources-and-corpus-pipeline.md) §9、§19-2；[05](05-data-platform.md) §3.1.2、§14.3-6；[01](01-vision-and-requirements.md) §13.5-2；SI-16、SI-29
- **与旧决策的关系**：revises D-007 的表示方式（`Paper` + `Identifier` 多值表 + `preprint_of` 边），D-007 的原则全部继承；D-031（弱信号观测级键与 tie-break）继承。
- **背景**：D-007 规定"预印本与正式版默认不合并为一条，以 `preprint_of` 互联，两版全文都保留"。v2 的三层身份把 arXiv v1、v2 与期刊正式版视为同一 Work 的不同 Version，若不说明，会被误读为"合并"了 D-007 禁止合并的记录。
- **决策**：
  1. **三层**：Work（一篇作品）/ Version（预印本 v1、v2、正式版等）/ Manifestation（具体载体：PDF、HTML、某源的记录）；内部键为 ULID，标识符多值（D-007）。
  2. **Version 的形成**：强标识符（DOI、arXiv id 等）经 union-find 归并为 Version。
  3. **Work 的形成**：多源投票的版本边（`version_of`）把 Version 归入 Work，物化为 `cluster_id`；自动接受的 `version_of` 边在身份金标集上的精确率 ≥0.99（09 AC-V1.29）。
  4. **与 D-007 的对齐**：预印本服务器上的预印本与期刊正式版是**同一 Work 的不同 Version**，各自保留元数据与全文，没有被合并成一条记录——D-007"不合并为一条、两版都保留"的要求照样成立；**工作论文系列（SSRN、NBER、各央行 WP 等）与发表版只建 `preprint_of` 关系边，不并入同一 Work**（标题常改、内容差异大，SI-16）。
  5. **弱信号不自动合并**：MinHash-LSH 与 Splink 只产候审对，进入管理员候审队列；合并日志可审计、可撤销，撤销后状态完全复原；输入顺序无关。
  6. 查询期按 `cluster_id` 折叠，同一作品的多个版本在同一列表内不重复计分（04 §8.5）。
- **理由**：三层身份让"同一研究的多个版本"在推荐与检索中只算一次，又不丢任何版本；WP 与发表版的边界沿用 v1 的经管领域经验。
- **影响**：05 的 `work`/`version`/`manifestation`/`version_edge`/`identifier_assertion`；v1 ETL 的 `paper_relation` 映射（05 §10.3）；AC-V1.26…V1.29、AC-V2.10、AC-V2.44。

## D-049 robots/ToS 统一规则：文档化 API 冲突、needs_confirmation、例外附表与漂移分档

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-05、§6.1-2、§6.1-5、§7-2、Q4、R2-13、R2-15、R2-16、R2-18；[08](08-compliance-security-privacy.md) §4、§14-10；[03](03-sources-and-corpus-pipeline.md) §6、§19-5、§19-9；名录 §2.2、§8.5；CP HC-29、HC-31；综合 G-03
- **与旧决策的关系**：supplements D-014（诚实 UA、robots 与 Content-Signal 遵守、敏感站白名单式抓取），D-014 的原则全部继承；推广 D-026（robots 路径级最长匹配读法）为全部主机的通用规则；满足 v1 AC-0.5"robots 明确禁止的路径不访问，记录例外需 ADR"——本条的**例外附表**即该 ADR 载体。
- **背景**：多个来源的文档化 API 与所在主机的 robots 冲突（NCBI E-utilities 与 FTP、ORCID、OSF、eLife、HAL、Zenodo、EBI FTP、PubChem、CiNii、IACR、arXiv export 等），bulk 主机（ftp.ncbi、ftp.ebi）的 robots 为 `Disallow: /`（综合 §8；AG 核验）。v1 各 adapter 自行声明允许路径，没有集中执行点；v2 平台化后必须有全库统一、可审计的规则。
- **决策**：
  1. **五通道取最严**：对每个请求同时评估文档化 API、bulk 快照、robots 路径、ToS 自动化条款、tdmrep，外加挑战信号；冲突时取最严者（P-05）。robots 按 RFC 9309 解析，最长匹配（D-026 推广）；robots.txt 返回 401、403 记为 `unreadable`（从严）；`ai-train=no` 等 Content-Signal 继续遵守（D-014）。
  2. **适用范围**：robots 约束平台侧与用户侧执行器的一切自动请求（`user_fetch`、`tdm_api`）；只有用户在场的导航（在出版社打开）与用户在场的一键保存（`tab_save`）不受约束（HC-29、08 R16）。robots 具名禁止 AI UA 的站点，不做扩展代发的 `user_fetch`，只提供"在出版社打开 + 打开后一键保存"，LQ-19 有结论后再议（R2-18）。
  3. **needs_confirmation**：文档化 API 与主机 robots 冲突、bulk 主机 robots 全禁、或条款不清的通道，状态为 `needs_confirmation`（HC-31）：取得书面确认前禁止后台批量；按需或用户触发的低频调用，须该主机先登记进本条的**例外附表**（08 R5），登记前平台对该主机零请求。**NCBI**（E-utilities、FTP）按简报 R2-13 更严：书面确认且登记进附表后才允许按需调用，此前由 Europe PMC + PMC 允许通道 + Crossref 承担（解决 01 审计遗留 C-3）。附表登记与修订走 ADR 流程（主 agent 起草、用户确认），记录范围、速率与有效期；沉默不等于同意。
  4. **书面确认**：确认登记写明范围、速率、有效期与原文存档；确认只放宽登记过的冲突与速率，不放宽挑战冷却与结构性上限；依赖书面确认运行的通道，遇 ToS 哈希变化或 robots 变严，**24 小时内回退**（比第 5 条的一般宽限更严，解决 01 审计遗留 C-2）。
  5. **漂移分档**（覆盖简报 §6.1-5 的措辞，R2-15）：robots 与 TDM 信号漂移立即降级；ToS 哈希变化给 7 天宽限，期满未复核只停后台收割；元数据通道自身受影响时暂停并切换替补链。降级只影响该通道的后台模式，已入库数据与本地读路径不受影响。
  6. **证据复核逾期**（R2-16）：`verified_at` 超过 90 天的通道，若漂移探针持续为绿且证据其余字段完整，进入 `review_overdue`，给 30 天宽限并维持原模式；宽限结束或任一探针告警，降为 `on_demand` 并标 `needs_confirmation`（⚠ 设计判断，V0 复核）。
  7. **例外附表初版**：08 §4.6 与 03 §6.8 所列主机全部以"待确认、零请求"建档；v1 对 `www2.nber.org` 的附条件放行（03 §3.4 所引的 v1 先例）经复核后迁入。
- **理由**：一条规则、一个执行点（出站网关读取策略引擎的判定）、一张附表，才能让"保守默认"（Q4）可审计，又给书面确认留出放宽的正式通道。
- **影响**：08 §4 的判定表 R1–R16；03 §6 的策略引擎；名录的 ⚑ROBOTS 闸门；02 出站网关读附表；AC-0.5、AC-0.12、AC-0.14；AC-V1.5…V1.12；V0-T3 的发函清单。

## D-053 受限全文的执行位置在用户侧

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-03、§6.3-3、§7-10、R2-18、R2-27、R2-28、R2-48；[02](02-architecture.md) §2.4、AD-02、INV-02、§8-3；[08](08-compliance-security-privacy.md) §5.1、§5.4、§14-1；[03](03-sources-and-corpus-pipeline.md) §12；CP HC-02、HC-03、HC-16、HC-32、LQ-07；01 审计遗留 C-10
- **与旧决策的关系**：在 v2 中 supersedes D-030 的平台侧使用（`browserfetch` 只在 pc-agent 中复用）以及 v1 以"服务端浏览器与会话代取"为前提的相关表述；revises D-003（`auth_gated` 的 backend 绑定改为 `exec_side=user`）与 D-006（人在回路登录继承，执行位置移到用户侧）；D-024 中 wiley 全文转用户侧；D-033 的抽取语义继承，执行位置按本条。
- **背景**：机构订阅（SERU、EZproxy）与出版商条款把访问权授予个人；平台若以自己的出口、持有用户会话代取全文，就成为未经授权的第三方访问者（HC-03、LQ-07），数据中心 IP 还会触发 EZproxy 的账号共享判定。
- **决策**：
  1. auth-gated 全文**只在用户显式触发时单篇取回，执行位置在用户侧**：浏览器配套扩展（Companion Extension）在用户本人浏览器会话中取回；或 pc-agent 在用户本机取回。平台服务器不以平台出口代用户访问出版商，不持有可用的出版商会话；平台服务镜像不打包用户级 AuthProvider、凭证库与 `browserfetch`。
  2. platform 部署的默认动作是"在出版社打开"；平台只下发签名的 RetrievalIntent 与声明式 FulltextRecipe，只接收不含内容、凭证与哈希的回执；"用你的凭证"状态只在用户侧计算。
  3. **不预取、不批量**：任何部署都没有批量取回 auth-gated 全文的入口，用户侧执行器串行、每域间隔 ≥6 秒、每平台每日 ≤200 次尝试（HC-32；AC-0.18）。唯一例外：personal 部署可"仅许可允许的 OA 全文，批量取回到本人私有空间"（R2-48，FR-87，Could），不涉及受限全文。
  4. **`deployment.host_is_user_device`**（默认 `false`）：personal 部署运行在用户本人设备上并声明为 `true` 时，意图直接派给同机 pc-agent；运行在云主机上时视同 platform，auth-gated 取回只能走扩展（R2-28）。
  5. **私有 PDF**（覆盖简报 §6.3-3 第三项，R2-27）：platform 部署默认只存设备本地；用户开启同步时服务端只存端到端密文、不可解密，不跨用户去重；服务端私有处理默认关闭。`server_envelope`、`dek_ref`、`processor='api:<vendor>'` 只在 personal 且 `host_is_user_device=true` 时可用，且 `api:<vendor>` 还须同时满足：用户显式同意 `llm_private_processing`、来源 `derivation.private_llm` 允许（IEEE 禁止、Elsevier 待确认）、第三方为零保留条款（01 审计 C-10 的三道附加闸，法律风险待 LQ-06）。
  6. robots 具名禁止 AI UA 的站点只提供"在出版社打开 + 一键保存本人标签页中的 PDF"（R2-18，D-049 第 2 条）。
- **理由**：把取回放在用户本人的会话、网络与设备上，是在不取得出版商新授权的前提下唯一与订阅条款一致的做法；平台保留"在出版社打开"作为永远可用的退路。
- **影响**：02 的 U2、U3 与 Egress 拒绝规则；03 §12；05 §3.2.7；07 §4.7；AC-0.13、AC-0.18；AC-V0.17、AC-V1.38、AC-V3.16…V3.21、AC-V7.6、AC-V7.7。

## D-054 用户级凭证与私有全文的端到端加密与多设备同步

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.3-3、R2-14、R2-29、R2-30；[08](08-compliance-security-privacy.md) §5.2–§5.6、§13 候选 14；[05](05-data-platform.md) §3.2.8；CP HC-04、HC-16
- **与旧决策的关系**：revises D-023（AES-GCM 凭证库：用户侧沿用，扩展为可多设备同步的端到端凭证库；服务端 `CredentialStore` 在 platform 部署下不使用）。
- **背景**：服务端 KMS 封装与客户端端到端加密是两种信任模型（综合 §8）；对 auth-gated 凭证，前者意味着平台持有可用的机构凭证，与 D-053 冲突。
- **决策**：
  1. **凭证分两类**：部署级上游 API key（Crossref 联系邮箱、NCBI key、OpenAlex/S2 key 等）属平台身份，**只由 Egress Gateway 读取**（docker secrets 或 0600 文件，外部 KMS 可选），全局调度；用户登录用的 OAuth 客户端密钥（如 ORCID 登录）归认证服务（R2-30）。用户级出版商凭证（机构会话、EZproxy 配置、TDM key、本人的 OpenReview 令牌）**平台服务端不可解密**，存于扩展或 pc-agent 的客户端凭证库。
  2. Springer Nature OA/Meta API 与 NASA ADS 在条款书面确认前按用户级凭证处理（R2-14）。
  3. **多设备同步**只传端到端密文，且只对 API key 类凭证开放；**会话 cookie 与 `storage_state` 属设备绑定凭证，一律不同步**（R2-29）。密钥层级：Vault Key（VK）在端侧生成；新设备须旧设备批准或恢复码入网；撤销丢失设备后轮换 VK、旧封装与旧恢复码失效。
  4. 平台不收机构密码；禁止池化、共享或跨用户使用任何凭证。
- **理由**：端到端加密让"平台不持有可用凭证"成为可验证的结构性质，而不是运维承诺。
- **影响**：05 的 `credential_blob` 只存密文；08 §5.3；AC-0.3、AC-0.10；AC-V3.15；v1 ETL 中 `[auth.*]` 键的分流（05 §10.3）。

## D-055 Egress Gateway：唯一出口、五元组令牌桶、全局配额账本与三道舱壁

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-04、R2-08、R2-37；[02](02-architecture.md) AD-01、INV-03、§2.3.13、§6.4-1；[04](04-retrieval-and-routing.md) §13、§18.2-4；[03](03-sources-and-corpus-pipeline.md) §5.5；[08](08-compliance-security-privacy.md) §1.4；CP HC-06、HC-10、HC-26
- **与旧决策的关系**：在 v2 中 supersedes D-039（任务优先级队列 defer）；D-030 的 S-c（`cf-mitigated: challenge` 判定）与 E-1（域级冷却）继承到网关与扩展；D-014 的诚实 UA 由网关统一注入。
- **背景**：多用户后，上游请求量若随用户数线性放大，会违反各源限额并招致封禁（P-04）；v1 的按域令牌桶、各 adapter 自行声明 robots 与冷却，不足以在多进程、多道任务下保证全局礼貌。v2 多用户下交互、收割与 enrich 必须分道，D-039 的"单用户 FIFO 足够"前提不再成立。
- **决策**：
  1. **Egress Gateway（出站网关）是平台侧唯一的对外出口**，由网络隔离强制：其余容器所在网络无公网路由；例外只有 Edge 的入站与 ACME 证书续期；异地备份采用拉取式，平台主机不为备份主动外连（R2-37）。03 的 PoliteHttp 是网关内部使用的客户端库，08 的"出站网关"即本组件。
  2. 网关分路由类处理上游数据源、身份提供方、LLM 提供方与通知出口；主机白名单外的请求（含重定向）一律拒绝；`exec_side=user` 通道的请求一律拒绝（D-053）；每次出站尝试在 FetchLog 恰有一行；任一主机的首个请求之前必有 robots 判定（D-049）。
  3. **令牌桶键为五元组** `(source, host, 上游请求类, 凭证, 出口 IP)`，出口 IP 维度只收紧、不叠加；响应头驱动的配额账本，以书面限额为上限做 AIMD；重试预算 ≤3 次/请求且 ≤10%；按"源 × 端点"熔断；遇挑战即停并冷却 24 小时，不求解；**禁止对同一第三方主机发对冲请求**；每个上游只用一个平台身份，禁止多 key、多 IP、住宅代理与 UA 伪装（HC-10）；arXiv 全平台合计每 3 秒 ≤1 次、单连接（HC-06）；OpenAlex 设美元预算桶。
  4. **三道舱壁**：交互、收割、enrich 各自有并发与令牌配额，由全局配额账本协调；交互道内的联邦请求受每用户日配额与全局美元预算封顶。
- **理由**：出口唯一才能让礼貌、robots、许可与审计有一个不可绕过的执行点；五元组与舱壁把"用户数增长"与"上游请求量"解耦。
- **影响**：02 §2.3.13、§2.5.3；04 §13；AC-0.5、AC-0.8、AC-0.12、AC-0.13；AC-V0.15…V0.18、AC-V1.1…V1.4、AC-V2.38。

## D-056 LLM 路由、AI 生成内容标识与数据出境

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-07、§7-11、R2-27、R2-45；[08](08-compliance-security-privacy.md) §9；[06](06-recommendation-and-matching.md) §17；[03](03-sources-and-corpus-pipeline.md) §11.4；[04](04-retrieval-and-routing.md) §4.5、§20-27；CP HC-11、HC-12、HC-22；综合 G-09、G-13

- **决策**：
  1. **不进交互热路径**：滑动、取批与事件路径上不同步调用 LLM；LLM 全部不可用时推荐与卡片照常工作（模板理由、作者摘要首句）。
  2. **T1 档默认不配 GPU**（R2-45）：涉及用户画像的 LLM 任务（画像摘要、带画像的 listwise 重排）只允许自托管模型，T1 默认关闭并回退到非 LLM 路径；只处理开放内容的论文侧预处理可用第三方 API，须为零保留条款、非中国境内路由；查询解析不使用第三方 API（04 §20-27 按从严读法）。
  3. **数据闸**：`data_class ≠ shareable` 的请求（私有全文、个人数据、受限公开内容）发往第三方 LLM 的次数为 0；唯一例外是 D-053 第 5 条的 personal 本机例外及其三道附加闸。共享的 AI 内容只由可共享来源派生；per_user 全文的派生摘要只存在该用户私域。
  4. **地区路由**：LLM 调用经出站网关的 `model_provider` 路由；各地区单元只调用 `llm.providers` 登记的端点；若面向中国境内用户（Q2），只路由到已备案或自托管模型（HC-12）。
  5. **生成即校验**：共享 TL;DR 与翻译经规则闸、NLI 闸、抽样裁判三道闸，不过闸降级为原文首句；提示注入防护（输入隔离、schema 约束、源外 URL 过滤）。
  6. **标识**：AI 生成内容显式标注（界面"AI"或"译"标与读屏前缀）、全局可关、永不替代作者摘要；导出与分享写入机器可读的隐式标识（`ai_label`：generated、provider、content_id、model、created_at）；第三方生成内容（如 S2 TLDR）注明来源。GB 45438—2025 的具体标识格式待读标准正文（⚠，G-13）。
- **理由**：把 LLM 限定在离线与近线、开放内容、可降级的位置，才能同时满足热路径延迟、成本上限（NFR-19）与数据出境约束。
- **影响**：02 的推理服务与网关路由；03 §11.4；06 §17；07 §8.8；AC-0.9、AC-0.16；AC-V1.14、AC-V1.34、AC-V1.35、AC-V4.28、AC-V5.14、AC-V6.9。

## D-058 TSRG：路由、调度、兴趣与反向推送的统一索引结构

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §5、§6.2-2、§7-7、R2-22、R2-38、R2-40；[04](04-retrieval-and-routing.md) §5、§6、§11、§12、§18.2-1、§19-1、§19-7、§19-14…§19-17；RT §3.5
- **与旧决策的关系**：新增（v1 无路由结构；v1 的 adapter 能力声明由 SCD 细化，D-046）。
- **背景**：用户要求"图/树等结构支持快速查找、并行查找与路由，提高准确率与稳定性"（需求 R2）。v2 有数十个异构来源，每个来源覆盖的学科、滞后与成本不同，而同一套主题结构还能服务收割调度、兴趣建模与论文→读者的反向推送。
- **决策**：
  1. **TSRG（Topic–Source Routing Graph）** 以 OpenAlex Topics 为骨架（domain 4 → field 26 → subfield 252 → topic 4,516），下挂 arXiv 分类、JEL、PhySH、MeSH、ACM CCS 等原生分类叶子（MSC2020 为默认不加载的可选插件，R2-22）；TopicNode 上挂 `route_stat`（覆盖、滞后、λ）；用户标签放在 `usr` 覆盖层，不进共享 TopicNode（R2-40）。
  2. **同一张图服务四件事**：查询路由、收割调度（按节点 λ 分配礼貌预算）、兴趣建模（画像挂在节点上，兄弟节点作探索臂）、论文→读者反向路由（节点倒排 → WatchKey/用户）；四者引用同一套 `topic_node.node_id`。
  3. **路由算法**：先求主题后验 P(t|q)，按"边际召回 / 成本"做预算贪心，并以"单项最优"兜底；近似界以可证的 ≥(1−1/e)/2 表述（文献结论 ≥0.405），在线对小规模做精确枚举（规模闸）、离线做部分枚举校验（R2-38）；Thompson sampling 做源探索，适用限制以 04 §19-7 为准；日志足够后升级为 GBDT 成对排序路由器。**路由不使用个人画像**（R2-40）。
  4. 图数据留在 PG 邻接表（在线查询 ≤2 跳），夜间导出 CSR 做 PageRank、共被引等批算；不引入独立图数据库。
- **理由**：一张图同时是路由的索引、调度的预算表、兴趣的坐标系与反向推送的倒排，避免四套相互漂移的主题体系；预算贪心有理论保证且在 ≤50 个源时为毫秒级。
- **影响**：04 §5–§6、§11–§12；05 §3.1.6–§3.1.7；06 的兴趣树与层②；AC-V2.22…V2.29、AC-V2.39、AC-V2.42。

## D-059 Query AST v2 与用户频道取代 v1 订阅 DSL

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.2-1、§6.2-3、§6.2-6；[04](04-retrieval-and-routing.md) §3、§4、§7、§18.2-2、§19-13；[01](01-vision-and-requirements.md) FR-34、FR-39、FR-40、§16-5
- **与旧决策的关系**：v2 中取代 v1 design/09（订阅 DSL、编译下推 + 本地补偿）的设计职能；v1 文档保持 implemented，v1 冻结代码仍按它运行。v1"下推尽可能多、正确性以本地过滤为准"的原则继承。
- **背景**：v1 的订阅 DSL 只服务"订阅 + 本地过滤"；v2 需要统一表达查询论文、最新论文、筛选、多来源与组合查询，并把频道编译为共享收割键。
- **决策**：
  1. **统一 Query AST**（布尔、字段、短语、语义、过滤、排序）；规范化 AST 的 `query_hash` 兼作缓存键与复现凭据。
  2. **意图**：LOOKUP、SEARCH、SIMILAR、LATEST，建议增列 EXPAND（引文扩展）为第五意图（04 §19-13；01 §16-5；待用户确认后以本条修订简报 §6.2-1 的"四意图"）。解析四步：规则快速路径 → 可选的 LLM 受约束结构化输出（非热路径，D-056）→ 只链到库内 ID 的实体链接 → 用户可编辑的筛选条。
  3. **裸词语义**：即席检索中的裸词为软检索文本（稠密通道可召回不含全部词的相关作品）；在频道中，以及按 recency、cites、issue、personal 排序时，裸词编译为硬 AND 门。
  4. **频道**：保存的 AST + 推送偏好；编译为带引用计数的 WatchKey，同键只收割一次；支持频道之间的并、交、差，组合结果可存为新频道。
  5. **健全放宽**：AST 先化为 NNF，再按极性替换来源不支持的子式（正极性 → true，负极性 → false），保证 P ⇒ P_s，精度由本地残差过滤恢复，本地分析器与远端对齐。
  6. **v1 兼容**：9 个预置包与存量订阅经 closed_world 模式转换，结果集与 v1 `filter_papers` 逐条一致（v1 代码作测试 oracle），SSRN 分类项进入 `needs_review`。
- **理由**：一套 AST 贯穿查询、频道、收割与推荐召回，避免多种查询语言各自漂移；closed_world 模式保证 v1 用户的订阅迁移无损。
- **影响**：04 §3–§4、§7；AC-V2.1…V2.8、AC-V2.16、AC-V2.30；v1 ETL 的订阅转换（AC-V3.29）。

## D-060 检索索引选型（修订 D-034 决策 6）

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.2-4、R2-39；[04](04-retrieval-and-routing.md) §8.5–§8.7、§9、§18.2-3；RT §3.5、§4.2、§12；综合 §8（B-01 行）
- **与旧决策的关系**：revises D-034 决策 6（PG 迁移路径规划为 `tsvector` 生成列 + GIN）；D-034 的"查询面单点封装"与"`--check` 与源表对账"两条原则继承；D-017 决策 4（FTS5 推迟）不适用于 v2。
- **背景**：v2 需要 BM25 排序、稠密向量召回与组合过滤；`tsvector` + `ts_rank_cd` 不是 BM25，排序质量不足以作为混合检索的词法通道。
- **决策**：
  1. **词法**：pg_textsearch（PostgreSQL 许可，只支持 PG 17/18）作 BM25 排序层；`tsvector`/GIN 作谓词层（D-034 决策 6 的方案降为谓词层）；ParadeDB（AGPL）只作可选（D-044）。
  2. **稠密**：pgvector `halfvec` HNSW + iterative scan，维度随 Q7 的表示选型；嵌入行带 `model_id`、`model_rev`、`input_basis`，新旧模型可并存。
  3. **融合与重排**：RRF（k=60 起步；外置引擎须显式设 k）；cross-encoder 重排的 top-100 是上限，纯 CPU 的 T1 档从小模型 int8、top-50 起步，超预算先发 RRF 结果、重排结果经流式 `upgrade` 补发，该降级路径占比 ≤5%（R2-39）。
  4. **过滤与已见**：组合过滤按选择率规划（位图/GIN 先求候选集，小集精确扫描，大集走 ANN）；分面与用户已见集合用 Roaring 位图。
  5. **性能口径**（R2-39）：800 ms 为端到端本地检索 p95；300 ms 为单路召回的升级触发线。
- **理由**：在单栈 PG 内用许可放行的扩展获得 BM25 + 向量的混合检索，避免引入独立搜索引擎；以 tsvector 保留谓词能力与回退路径。
- **影响**：04 §9；05 的 `work_search` 与嵌入表；v1 FTS5 与 v2 BM25 的查询语法与排序不可逐项等价（D-034 已如实入档），ETL 只出 overlap@10 对照报告（ETL-V7）；AC-V2.9…V2.13、AC-V2.46。

## D-061 推荐分阶段栈 R0→R1→R2 与 ValueModel 配置化

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.4-1…§6.4-4、§7-8、R2-42、R2-43、R2-44；[06](06-recommendation-and-matching.md) §7、§8、§16、§23.3-1；SM §3-1…§3-4；SR §2.6
- **与旧决策的关系**：新增（v1 无推荐）。
- **背景**：1 万用户以内，数据量与算力都不支持在线训练集群或生成式端到端推荐；同时需要从第一天起可解释、可控、可评测。
- **决策**：
  1. **Candidate Pipeline** 六类组件（Source、Hydrator、Filter、Scorer、Selector、SideEffect，沿用 X 开源架构抽象）；召回至少 5 路，每条候选带来源归因；单路失败只降级。
  2. **R0**：规则化 ValueModel + 每用户逻辑回归，训练在共享论文嵌入上，每次反馈异步增量更新（事件到达后 p95 ≤2 秒生效），显式负例与随机负例分别加权；纯 CPU。**R1**：多行为 GBDT/LTR、协同召回、Thompson/LinUCB、DPP/MMR。**R2**：序列多行为模型，只在 06 定义的规模与数据阈值达到后启用。每次升级须有离线与在线（interleaving 或 A/B）双重对照、显著收益才替换。
  3. **ValueModel**：`score = Σ V_a · P̂(a)`，V 为版本化配置并带变更日志与 lint：负向行为用大绝对值权重，"不感兴趣 + 原因"的权重绝对值至少是左滑的 10 倍，`export_citation` 为最高正向，dwell、view_figure、share 权重为 0；净负分候选排在所有非负候选之后。
  4. **有限批次**：默认 25 张，可选 15 / 25 / 35；**禁止用净负分候选补满批次**，候选不足时批次提前结束；"再来 10 篇"以低强调文字链接呈现、只在用户点击后下发，每日上限 60 ⚠（R2-42）。
  5. **重排与探索**：作者衰减、venue/主题配额、DPP（θ 从 0.5 起调）或 MMR；默认强度下 10–20% 探索槽并标注"探索"，约 2% 随机探针记录倾向分；新论文用分级曝光（D-063）。
  6. **北极星**：每周每个活跃用户的有价值阅读数（收藏、4 星以上评分、导出引用、打开全文，四者去重），另设 VR-strict（不含 `open_fulltext`）作诊断；排除本人认领作品、单次批量导出 >5 篇与匿名会话（R2-44）。时长与日活只作护栏。
- **理由**：R0 在小样本下已被学术推荐实践验证（Scholar Inbox 配方），且完全可解释；分阶段升级把复杂度推迟到数据足以支撑的时候。
- **影响**：06 §7–§8、§16；AC-V4.1…V4.10、AC-V4.15、AC-V6.8。

## D-062 事件契约、曝光绑定、ID 生成与公共信号准入

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.4-6、§6.5-6、R2-06、R2-07、R2-31、R2-32、R2-33、R2-43、R2-47；[06](06-recommendation-and-matching.md) §5、§23.3-2；[05](05-data-platform.md) §3.3、§14.3-3；[02](02-architecture.md) AD-04、§2.3.11、§2.9、§6.4-4；CP HC-02

- **决策**：
  1. **06 是事件名与字段的唯一权威**，05 落表，07 与 demo 引用（R2-06）；21 个必选事件与 15 个扩展事件都有版本化 JSON Schema，前端 SDK 与服务端从同一 schema 生成；↑ 的界面文案为"跳过"，事件为 `skip_up`，中性、不计负反馈。

- **理由**：一处定义、多处生成，才能让契约测试捕获漂移；曝光绑定是离线评测与去偏的前提（P-08）。
- **影响**：05 §3.3；06 §5；07 §16；AC-V3.8、AC-V3.9、AC-V4.4…V4.6、AC-V4.25、AC-V5.27、AC-V5.28。

## D-063 新论文曝光下限：资格集合与全局预算

- 状态：proposed · 日期：2026-09-27 · 依据：简报 R2-41；[06](06-recommendation-and-matching.md) §10.3–§10.5、§23.3-5、§24 A1；[01](01-vision-and-requirements.md) §16-9
- **与旧决策的关系**：修订简报 §6.4-4 与 §6.4-5② 的"新论文和新作者……设曝光下限""每篇曝光下限"表述。
- **背景**：06 的容量算术表明，T1 档每日约 1.75 万次 Deck 曝光，而日新增收割 1–3 万篇（B-04）；即使每篇只保 20 次曝光，全部新论文也需 20–60 万次，远超总曝光，"每篇下限"不可行。
- **决策**：
  1. 曝光下限**只对资格集合生效**：新作者或小领域作品，且有足够的合格受众；受**全局预算约束：下限曝光 ≤5% 的期望曝光**。
  2. 其余新作品靠**贝叶斯分级曝光**：内容先验 + Thompson，按后验下界逐级扩大受众环；晋级时按相对基线的提升重置先验。
  3. 下限计数只认"下发且确认可见"的曝光（有对应 `impression` 事件）；作者行使拒绝权（`author.status='suppressed'`）后失去新作者下限资格。
  4. 层②反向推送在"每用户日预算 + 资格集合下限"约束下分配（贪心；硬配额用最小费用流）。
- **理由**：把"扶持新作者"限定在可承受的预算内，既防止新论文淹没个性化，也避免对全部新论文作出无法兑现的承诺。
- **影响**：06 §10–§11；FR-51、FR-59；AC-V4.9…V4.13。

## D-064 k 匿名阈值与差分隐私决策点

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.4-6、R2-04、R2-19；[06](06-recommendation-and-matching.md) §14、§23.3-3；[08](08-compliance-security-privacy.md) §7.2、§16；[05](05-data-platform.md) §2.5；CP HC-30；SM §4
- **与旧决策的关系**：新增。
- **背景**：协同信号、协同类解释与公开计数都可能暴露个体行为；k 匿名是最小防线，差分隐私是否必要尚无结论（SM §4-4）。
- **决策**：
  1. 三个参数：`k_cf`（协同信号入模）、`k_reason`（协同类 why-this 理由）、`k_show`（公开计数与社会证明）（R2-04）；R0 下限 `k_show ≥ 5`；初值以 06 §14.2 为准（5 / 5 / 10 ⚠），V4 开工前确认。
  2. 聚合只在 `evt.agg_*`，单元的不同用户数须 ≥ 所适用的 k；私有库共现不入协同；由私有文献库派生的细粒度收割键同样受 `k_cf` 约束（R2-19，D-043）。
  3. 用户可关闭"参与匿名协同统计"，自下一个聚合周期起其事件不进入聚合。
  4. **差分隐私决策点**：在 V6 公开计数上线前完成是否对聚合计数加差分隐私的决策，并以新 ADR 或本条修订记录（09 AC-V6.5）。
- **理由**：先以 k 门槛保证最低保护，把 DP 的成本收益放到有真实公开计数需求时再评估。
- **影响**：05 聚合闸；06 §14；08 §7.2；AC-0.17；AC-V4.25…V4.27、AC-V6.5、AC-V6.6。

## D-065 研究者匹配的 opt-in 边界

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.4-5③、Q5、R2-46；[06](06-recommendation-and-matching.md) §11.4、§23.3-4、§24 A9；[08](08-compliance-security-privacy.md) §6.3；[07](07-frontend-interaction.md) §10.6；CP HC-18；综合 G-14
- **与旧决策的关系**：新增。
- **背景**：研究者↔研究者互惠匹配能帮助合作与交流，但也可能暴露阅读轨迹、招致骚扰；真实需求尚未验证（G-14）。
- **决策**：
  1. 默认关闭；**双方都选择加入才启用**；三项同意分别勾选，不与注册或其他同意捆绑，每次授予与撤回各留一条记录。
  2. 匹配只使用用户**主动公开的研究画像**；私有阅读行为（滑动、收藏、评分、笔记、全文）永不进入匹配输入，建议卡的字段白名单中不含任何阅读行为。
  3. 年龄门槛 ≥18 ⚠（第二次中性年龄声明）；撤回后 ≤1 分钟停止展示、≤24 小时删除匹配资料与待展示建议（R2-46）。
  4. 尊重作者对"基于公开论文生成画像"的拒绝。
  5. 互惠分取调和平均，加容量与公平约束；上线前置条件为 G-14 用户访谈（默认假设 Q5），不早于 V6。
- **理由**：把匹配做成严格 opt-in 与只用公开信息，是在需求未验证时把隐私风险降到最低的做法。
- **影响**：06 §11.4；08 §6.3；07 §10.6；AC-V6.7。

## D-066 审计日志：HMAC 假名、哈希链、单写者与每日锚点

- 状态：proposed · 日期：2026-09-27 · 依据：简报 R2-36；[08](08-compliance-security-privacy.md) §11.3；[05](05-data-platform.md) §3.4、§14.3-7；CP HC-14、HC-28
- **与旧决策的关系**：新增；v1 的 obslog 与 FetchLog 演进为 `ops.fetch_log`、`ops.decision_log` 与 `ops.audit_log`。
- **背景**：跨用户可见内容要可追溯到来源许可，取回与请求要有防篡改的审计；同时审计日志本身不得成为个人数据的泄露点，并须与删除权兼容。
- **决策**：
  1. 审计行的主体只存 HMAC 假名 `subject_ref`，不存明文 `user_id`；审计假名密钥与归档假名密钥分离。
  2. 决策链与审计链分开，各自为**哈希链**；写入经暂存表由**单一写入者串行**链接，入链延迟 p99 ≤60 秒（设计值）。
  3. 每日生成签名锚点并导出；删除主体密钥后行哈希不变、链校验仍通过。
  4. 日志留存 ≥6 个月；影响评估记录与配置、模型变更留痕 ≥3 年（HC-14）。
- **理由**：哈希链加外部锚点让篡改可检出；假名化让审计与删除权可以同时成立。
- **影响**：05 §3.4；08 §11.3；AC-V1.41。

## D-067 数据权利实现与备份：导出、注销、加密粉碎与拉取式异地备份

- 状态：proposed · 日期：2026-09-27 · 依据：简报 P-06、R2-37；[05](05-data-platform.md) §5、§7、§9、§14.3-4、§14.3-8；[08](08-compliance-security-privacy.md) §6.2、§6.4；[02](02-architecture.md) §2.6.5；01 NFR-25、NFR-27；CP HC-20
- **与旧决策的关系**：新增。
- **背景**：多用户平台须支持导出、删除与注销，而备份、归档与审计又需要保留数据；平台还要求出站唯一（D-055），推送式备份会破坏该不变式。
- **决策**：
  1. **DSR 状态机**：导出发起后 ≤24 小时生成导出包（BibTeX、RIS、JSON，覆盖全部个人数据类），链接一次性、7 天过期；单项删除下一批次生效。
  2. **注销**：7 天宽限期；自申请起 ≤30 天（含宽限）完成 `usr`、`evt`、对象存储的删除；对每用户密钥做**加密粉碎**；擦除账本外置，恢复备份后重放擦除；备份按 35 天滚动淘汰（⚠ 时限待 08 与法务确认）；`learning_reset_at` 水位用于重置学习。
  3. **保留**：按 TTL 策略类执行保留作业，TTL 清理与 DSR 由不同角色执行；legal hold 优先于清理。
  4. **备份**：PITR；异地备份默认**拉取式**：异地主机持续拉取 WAL，平台主机不为备份主动外连（R2-37）；RPO ≤5 分钟、RTO ≤4 小时（NFR-27，设计目标）；月度恢复演练含擦除重放与 RLS 复验；personal 部署提供一键备份与恢复。
- **理由**：加密粉碎与外置擦除账本解决"备份里还有被删数据"的问题；拉取式备份保住出站唯一不变式。
- **影响**：05 §5、§7、§9；AC-V3.12…V3.14、AC-V3.27、AC-V3.28。

## D-068 API 契约：OpenAPI 3.1、URI 主版本与 SSE 流式语义

- 状态：proposed · 日期：2026-09-27 · 依据：简报 B-05、§6.5-6；[02](02-architecture.md) AD-09、§2.8、§6.4-2；[04](04-retrieval-and-routing.md) §8.2
- **与旧决策的关系**：新增（v1 为 CLI）。
- **背景**：PWA、扩展、pc-agent 与未来的只读 API/MCP 都依赖同一组接口；联邦检索需要"本地先返回、远端流式补齐"。
- **决策**：
  1. REST + SSE；**OpenAPI 3.1** 为契约，随构建生成并提交；URI 主版本 `/api/v2`，v2 内不做破坏性变更（oasdiff 类工具检查）；RFC 9457 错误体；游标分页。
  2. 联邦检索用 SSE：本地结果先返回，远端结果以 `upgrade`/`append` 补发，缺失与超时来源列入 `missing_sources`，`done` 必达；断线按 `Last-Event-ID` 续传，可落到其他副本；用户已看到的条目不移位。
  3. 扩展与 pc-agent 走 OAuth 2.1 PKCE。不采用 GraphQL（契约与缓存更复杂，收益不明）。
- **理由**：OpenAPI 让前端、扩展与契约测试从同一份定义生成；SSE 满足单向流式，比 WebSocket 简单。
- **影响**：02 §2.8；AC-V0.19、AC-V2.32、AC-V2.34。

## D-069 事务性 outbox 与 PG 原生队列

- 状态：proposed · 日期：2026-09-27 · 依据：简报 B-05；[02](02-architecture.md) AD-06、§2.9、§6.4-3；RT §10.6；综合 §8（B-05 行）
- **与旧决策的关系**：新增；v1 的 `tasks.py` 单一 FIFO 队列只适用 v1。
- **背景**：领域事件（如 `corpus.change`）须与数据写入一致，且至少投递一次；T1 档不宜引入独立消息中间件。
- **决策**：
  1. 领域事件与业务数据在同一事务写入 `ops.outbox`；relay 发布到 PG 原生队列，**procrastinate 为首选、pgqueuer 为备选**；消费者幂等，按业务键去重。
  2. 需要 LISTEN 的组件使用直连或会话池连接（事务池模式的连接池不支持 LISTEN，RT §10.6）；三道舱壁（D-055）映射为独立的工作者池。
  3. T1 档不引入 Kafka 等外部消息中间件。
- **理由**：事务性 outbox 消除"写库成功、发消息失败"的不一致；PG 原生队列与单栈一致（D-042）。
- **影响**：02 §2.9；AC-V2.45。

## D-070 对象存储：ObjectStore 抽象，不选 MinIO

- 状态：proposed · 日期：2026-09-27 · 依据：[05](05-data-platform.md) §6、§14.3-5；[02](02-architecture.md) §2.6.3；D-044；RT §12-30
- **与旧决策的关系**：新增。
- **背景**：共享 OA 资产、私有资产密文、快照与归档需要对象存储；MinIO 为 AGPL-3.0，且仓库已归档、README 声明不再维护（05 §6.5，2026-09-27 核验）。
- **决策**：
  1. 应用经 `ObjectStore` 接口访问存储，只依赖 S3 API 的最小子集，保证后端可替换。
  2. 默认后端为本地盘；自托管 S3 兼容存储首选 SeaweedFS（Apache-2.0），RustFS（Apache-2.0）为备选；云厂商 S3 兼容服务可选，但须满足地区单元的数据驻留（D-057）。
  3. 不选 MinIO（违反 D-044 的默认门禁与依赖健康要求）。
  4. 前缀分区：共享 OA（`oa-shared/`）、私有（`private/`，按用户命名空间、只存密文或 personal 本机信封）、快照与归档；不跨用户内容寻址去重。
- **理由**：抽象层保住"不锁定"（NFR-24），许可与维护状态决定默认选择。
- **影响**：05 §6；02 §2.10.3 的 MinIO 行按本条更新。

## D-071 GROBID 启用 `teiCoordinates=figure`（修订 D-033 与 design/12）

- 状态：proposed · 日期：2026-09-27 · 依据：简报 §6.5-4、§7-13；[02](02-architecture.md) §2.3.9、§6.2；[07](07-frontend-interaction.md) §8.5；[08](08-compliance-security-privacy.md) §3.5；CP HC-06、HC-09
- **与旧决策的关系**：revises D-033（extract 语义：pypdf 基线 + GROBID 可选增强）与 [design/12](../../archive-v1.md#docs-design-12-fulltext-extract-md) 的 GROBID 调用参数；consolidation 硬编码为 0 的约定继承。

- **决策**：
