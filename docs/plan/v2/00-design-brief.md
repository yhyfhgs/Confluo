## 2. 产品定义

**一句话**：面向研究者的跨学科论文发现平台。它从合法来源持续收割论文，用可解释的个性化推荐把"今天值得看的论文"做成一叠卡片，用户靠滑动分拣。用户自己的机构权限只用于本人取回全文。

- **差异化定位**（依据 market 调研 I-1）：跨学科（尤其包含经管金融 WP），卡片分拣交互，学习型个性化，推荐可解释，用户自带权限取全文。现有产品没有同时做到这五点的。
- **不做**：AI 综述/问答主战场（集成开放服务即可）；社交网络化的时长竞争；任何形式的全文再分发。
- **北极星指标**：每周每个活跃用户的"有价值阅读数"（收藏、4 星以上评分、导出引用、打开全文，四者去重计数）。时长与日活只作护栏指标。每日推送是**有限批次**，看完就结束。`open_fulltext` 只计入本人模型与北极星统计，不进入任何公共热度信号，以免暴露"有人拥有访问权"（HC-02）。

## 4. 核心架构原则（P-xx，全部文档共同遵守）

- **P-01 先收割、后联邦**：订阅、最新论文、卡片流**只读本地语料**。即席查询先查本地，覆盖不足时才在查询时联邦到远端源（依据：retrieval §3.5、§12.1）。
- **P-02 合规数据三域**：
  - `corpus` 共享层：只放公开元数据，以及许可允许再分发的内容与其派生物；
  - `usr` 私有层：启用 RLS，放偏好、反馈、凭证、私有全文及其一切派生物；
  - `evt` 事件层：只追加，按月分区。
  - 另设 `ops` 运维域。

  每个可展示字段带 `display_scope ∈ {public_shared, per_user_only, link_only}`，每个资产带 `license_code`。
  `display_scope` 与合规调研的展示级别 V0–V4、权利类别 M1–M25 的映射由 [08](08-compliance-security-privacy.md) 定义。
  在法律问题 LQ-05 有结论前，B 类摘要（出版方版权、公开分发）不得作为 `public_shared` 派生物（TL;DR、翻译）的输入。
  **派生继承最严规则**：由 per_user 内容派生的任何东西（嵌入、TL;DR、特征、解释文本）一律 per_user，不得进入共享索引、全局模型、协同信号或他人可见的解释。
- **P-03 用户自有凭证，取回在用户侧执行**：凭证、配额、订阅全文**按用户隔离**，不池化、不共享、不预取。auth-gated 全文**只在用户显式触发时**单篇取回，**执行位置在用户侧**：
  - 浏览器配套扩展（Companion Extension）在用户本人浏览器会话中取回；
  - 或 personal 部署 / 本地代理在用户本机取回。

  平台服务器**不以平台出口代用户访问出版商**，也不持有可用的出版商会话（依据：合规调研 HC-03、LQ-07，SERU/EZproxy 条款）。platform 部署的默认动作是"在出版社打开"外链。用户取回的 PDF 可选上传到本人私有空间（HC-16）。
- **P-04 全局礼貌**：对每个上游的请求量**不随用户数线性放大**。限速按 `(source, host, 请求类, 凭证)` 设平台级共享令牌桶，由响应头驱动，以书面限额为上限做 AIMD；禁止多 key、多 IP 规避限额；禁止对同一第三方主机发对冲请求；遇挑战门一律停止，不求解。
- **P-05 最严者为准**：对每个源同时评估文档化 API、bulk 快照、robots 路径、ToS 自动化条款、tdmrep 五个通道，冲突时取最严者。冲突与未确认条款由策略引擎标记为 `needs_confirmation`（见 §8 待决 Q4）。
- **P-06 一切可解释、可控、可导出**：每张卡带 why-this 理由码；兴趣标签可查看可删除；提供一键非个性化视图；用户数据可导出（BibTeX/RIS/JSON）、可删除。
- **P-07 LLM 不进交互热路径**：LLM 只做离线或近线任务（论文侧共享预处理、画像摘要、每日批量 top-K 重排、懒生成解释）。滑动路径上不同步调用 LLM。AI 生成内容一律标注，且只基于可共享的开放内容生成共享版本。私有全文默认不发送给第三方 LLM API；面向中国境内用户时，LLM 须使用已备案模型，并完成属地登记与公示（HC-12；自托管本身不等于备案，见 §11 R3-18）。
- **P-08 评测先行**：从第一天起记录曝光日志（位置、候选源、打分分量、实验桶、倾向分），每个算法模块自带离线基准与在线指标。
- **P-09 可降级**：每个关键能力至少有两级同能力替补链（与 NFR-13、SI-22 一致）。任一上游失败时，系统降级为"仅本地/仅元数据"，不整体失败。

## 5. 统一术语（设计阶段草案词表）

所有文档使用以下名称；新增共享术语须在 [01](01-vision-and-requirements.md) 的术语节登记。

| 术语 | 含义 |
|---|---|
| **Source** | 一个可对接的来源（出版商平台、预印本服务器、聚合器、仓储实例……），分 `L1`（一级）/ `L2`（二级） |
| **SourceSpec v2** | Source 的机读声明（YAML），由 v1 VenueSpec 演进而来；含三个 **Channel**：`metadata` / `latest` / `fulltext`，每个 channel 声明方法、端点、认证、限速、robots/ToS 结论、许可策略和证据（url + verified_at） |
| **SCD** | Source Capability Descriptor：可下推谓词、排序键、增量游标、分页上限、成本模型、礼貌参数。是路由器与健全放宽的唯一输入 |
| **Connector / ConnectorFamily** | v2 的 adapter 抽象。家族包括 `aggregator_api`、`oai_pmh`、`feed`（RSS/eTOC）、`crossref_delegated`、`platform_family`（Atypon/Silverchair/OJS/HighWire…）、`official_tdm_api`（按用户 key 的 TDM API，与 auth-gated 全文同样在用户侧执行）、`site_special`（专站）；v1 adapter 经 `v1_bridge` 包装复用。每个 connector 声明执行位置 `exec_side ∈ {platform, user}` |
| **Venue** | 期刊、会议或 WP 系列，**独立于 Source**。venue 用多键归一（ISSN 集合、ISSN-L、OpenAlex source id、DBLP key、OpenReview 前缀），带演化边（`renamed_to`、`journalized_as`、`co_hosted_on`） |
| **Work / Version / Manifestation** | 三层身份模型：一篇作品 / 其版本（预印本 v1、v2、正式版）/ 其具体载体（PDF、HTML、某源记录）。去重结果以 `cluster_id` 物化 |
| **Policy Engine** | 依据 SourceSpec 合规字段与漂移探针结果，判定某请求是否允许、以何种模式（后台/用户触发/仅外链）执行 |
| **TSRG** | Topic–Source Routing Graph，主题-来源路由图，v2 的核心索引结构，见 §6.2 |
| **TopicNode** | TSRG 的主题节点。骨架为 OpenAlex Topics（domain 4 → field 26 → subfield 252 → topic 4,516），下挂 arXiv 分类、JEL、MSC2020、PhySH、MeSH、ACM CCS 叶子与用户标签 |
| **WatchKey** | 多用户共享、带引用计数的收割键：由用户频道编译而来，同键只收割一次 |
| **Percolator** | 新论文入库时反向匹配全部频道与兴趣画像，把论文写入对应用户的 **FeedInbox** |
| **Channel（用户频道）** | v1 Subscription 的 v2 形态。用户保存的查询 AST + 推送偏好，是推荐的显式召回源之一 |
| **Query AST** | 统一查询语法树（布尔、字段、短语、语义、过滤、排序），由 v1 订阅 DSL 演进而来 |
| **Deck / Batch** | 前端"今日分拣"卡叠 / 一次下发的有限批次（默认 20–30 张） |
| **Impression** | 一次曝光记录。所有训练用反馈必须绑定 `impression_id` |
| **ValueModel** | 排序打分 `score = Σ V_a · P̂(a)`：行为价值权重乘以预测行为概率，可版本化配置 |
| **Candidate Pipeline** | 推荐管线的六类组件：Source（召回源）、Hydrator、Filter、Scorer、Selector、SideEffect（沿用 X 开源架构抽象） |

## 6. 子系统裁决

### 6.1 来源与语料流水线（→ 03）

1. **两层来源模型**：
   - L1：`publisher`、`preprint`、`journal_platform`、`conference_platform`；
   - L2：`repository`、`aggregator`。

   Source 与 Venue 分离。多数出版商期刊**不需要写代码**：登记 SourceSpec 与 venue 即可，由 `crossref_delegated` 接管元数据与最新论文；全文走 OA 定位链或用户凭证。
2. **元数据主干与增量**：
   - 期刊与带 DOI 的 WP 以 Crossref 为主干。venue 枚举走 `/journals/{issn}/works`；最新论文以 `from-created-date` 加重叠窗口为主，`from-index-date`（结果放大约 100 倍）只作补漏，并做标识符去重；
   - 生命科学以 Europe PMC / PubMed 为主干；
   - 预印本走各平台原生通道（arXiv OAI 类目级 set、bioRxiv API、OSF 等）；
   - OpenAlex 季度快照加 PubMed baseline 等 bulk 通道构成本地底座，按全体用户兴趣的并集导入子集，计量 API 只做增量与补查。bulk 主机（如 ftp.ncbi、ftp.ebi）的 robots 同样纳入 §7-2 的 robots ADR 逐站登记。
3. **摘要补齐链按出版方路由**，每条摘要记 `abstract_source` 与 `abstract_rights`。缺摘要时降级展示，推荐冷启动不依赖摘要。
4. **只为有官方 API/协议通道的站点写代码**。WAF 或 robots 全禁的出版商站点不写抓取型 connector，只做元数据与外链，或由用户本人单篇触发。
5. **策略引擎 + 漂移探针是一等公民**：周期比对 robots/ToS 哈希、tdmrep、挑战率、配额头、DOI 前缀与 member 变化。发现漂移即告警，并自动降级到"仅元数据"。
6. **语料流水线**（v1 六阶段的 v2 形态）：harvest → normalize → identify（union-find `cluster_id` + MinHash-LSH/Splink 候审）→ enrich（摘要补齐、主题标注、嵌入、可共享 TL;DR）→ index（BM25 + 向量 + 图）→ percolate（写入用户 FeedInbox）。**全文 fetch 从后台流水线中移出**，改为用户触发的按需服务。
7. **支持名录**：机读注册表（`registry/sources/*.yaml`，实现期落地）为单一事实来源，文档形态为 [catalog/source-directory](../../catalog/source-directory.md)。每条记录的状态取以下之一：`v1-implemented` / `v2-P0` / `v2-P1` / `v2-P2` / `metadata-only` / `link-only` / `user-import-only` / `excluded`。允许写作 `metadata-only（P1）`，以区分登记优先级。

### 6.2 检索与路由（→ 04）

1. **Query AST + 四意图路由**：
   - LOOKUP：精确找某篇（标识符或标题）；
   - SEARCH：元数据或关键词检索；
   - SIMILAR：语义或相似检索；
   - LATEST：新论文 feed。

   另有组合查询（AST 中的布尔组合，以及多个 Channel 的并、交、差）。查询解析分四步：规则快速路径 → LLM 受约束结构化输出（可选、非热路径时）→ 实体链接 → 用户可编辑的筛选条。
2. **TSRG 路由算法**（本项目回应"图/树算法"需求的核心）：
   - 查询先求主题后验 P(t|q)。
   - 沿 TopicNode 上挂的 `route_stat`（覆盖、滞后、λ）与 SCD，按"边际召回 / 成本"做预算贪心选源。覆盖函数为单调次模：只有基数约束时，纯贪心有 (1−1/e) 近似；带成本预算时，采用"贪心 + 单项最优"兜底，取得常数近似。候选源通常 <20 个，可精确枚举做校验；≤50 个源时，路由计算为毫秒级。
   - 用 Thompson sampling 做源探索；日志足够后升级为 GBDT 成对排序路由器。
   - 同一张图同时服务四件事：查询路由、收割调度（按节点 λ 分配礼貌预算）、兴趣建模（用户画像挂在节点上，兄弟节点作探索臂），以及论文→读者反向路由（节点倒排 → WatchKey/用户）。
3. **健全放宽**：AST 先化为否定范式（NNF），再按极性替换源不支持的子式（正极性 → true，负极性 → false），保证 P ⇒ P_s；精度由本地残差过滤恢复，本地分析器与远端对齐。
4. **本地混合检索**：
   - BM25（默认 pg_textsearch，PostgreSQL 许可；ParadeDB 为 AGPL，只作可选）+ 稠密向量（pgvector `halfvec` HNSW + iterative scan）经 RRF（k=60 起步，外置引擎须显式设 k）融合，再用 cross-encoder 重排 top-100；
   - 组合过滤按选择率规划：位图/GIN 先求候选集，候选集小时精确扫描，大时走 ANN；
   - 用户已见集合用 Roaring 位图；
   - 图数据留在 PG 邻接表（在线查询 ≤2 跳），夜间导出 CSR 做 PageRank、共被引等批算。**不引入独立图数据库。**
5. **并行与稳定**：
   - 联邦 fan-out 是有截止时间的并行执行，按源 AIMD、重试预算（≤3 次/请求，≤10% 占比），按"源 × 端点"熔断；
   - 舱壁分三道：交互、收割、enrich；
   - 缓存不依赖 ETag，用应用层 TTL 缓存，TTL 与该源的 λ̂ 挂钩；
   - 部分失败时返回部分结果，并标注缺失的源。
6. **新鲜度调度**：频道编译为 WatchKey（引用计数去重）。日历型源按发布窗口轮询；连续型源用 Gamma-Poisson 估计 λ，在礼貌约束下做注水分配。

### 6.3 多用户数据平台（→ 05）

1. **Pool 多租户**：`corpus` 共享只读（写入只经 ingest 角色）；`usr` 全表 RLS，应用角色不是表 owner、没有 BYPASSRLS，用户上下文用 `SET LOCAL` 设置；`evt` 只追加，按月分区，事件 id 由客户端生成以实现幂等；`ops` 放队列、健康、配额账本、策略快照。
2. **身份与账号**：邮箱/密码 + OAuth（ORCID 用于作者认领与导入）。公开评论须完成实名锚定（ORCID 或机构邮箱之一）；若将来面向中国大陆（Q2），须改为后台实名，ORCID 或机构邮箱不一定满足。
3. **凭证分两类**：
   - **部署级凭证**：NCBI key、Crossref 联系邮箱、OpenAlex/S2 key 等，属平台身份，服务端 KMS 管理，全局调度（P-04）。
   - **用户级出版商凭证**：机构会话、EZproxy、出版商 TDM API key，**平台服务端不可解密**。这类凭证存在客户端（扩展/本地代理，沿用 v1 D-023 的 AES-GCM 凭证库）；如需多设备同步，只同步端到端加密的密文（HC-04）。平台不收机构密码。
   - 用户取回后选择上传的私有 PDF，存对象存储的按用户命名空间，不跨用户去重（HC-02）。
4. **用户侧数据**：
   - 画像：兴趣树节点权重，长期与短期两套；
   - 频道：查询 AST；
   - 文献库：状态、标签、笔记；
   - 反馈、评分、评论（visibility 取 `private` 或 `public`）；
   - 已见位图、实验分桶；
   - 导出与删除请求。
5. **特征存储暂缓**：用 PG 物化表，按需加 Valkey（BSD）；事件超过 10⁹ 行/年后再引入 ClickHouse。
6. **迁移**：新 schema 起步；v1 SQLite 走只读 ETL，用 COPY 导入；派生结构（索引、向量、cluster）在 PG 侧重建。

### 6.4 推荐与双向匹配（→ 06）

1. **Candidate Pipeline** 六类组件。召回源：
   - 显式关注（频道、作者、venue），相当于 X 的 in-network；
   - 长期与短期兴趣的多质心 ANN；
   - 文献耦合与引文图邻域；
   - 兴趣树邻近节点（探索）；
   - 同簇热门与开放热度信号（HF upvotes、GitHub stars 等，各源条款逐一核验）；
   - 新论文分级曝光池；
   - R1 起加入协同过滤。

   每条候选带来源归因。
2. **分阶段模型**：
   - **R0**：规则化 ValueModel + 每用户逻辑回归，训练在共享论文嵌入上（Scholar Inbox 配方，每次反馈即时增量更新），显式负例与随机负例分别加权；
   - **R1**：多行为 GBDT/LTR、协同召回、Thompson/LinUCB 探索、DPP/MMR 重排；
   - **R2**：序列多行为模型，只在规模与数据达到升级阈值后启用。

   1 万用户以内不引入在线训练集群，也不引入生成式端到端推荐。
3. **ValueModel**：`score = Σ V_a · P̂(a)`，V 版本化配置。负向行为用大绝对值权重，净负分沉底。左滑是弱负反馈；"不感兴趣 + 原因"是强负反馈，两者至少差一个数量级，强负反馈当次会话即生效。
4. **重排与探索**：作者衰减、venue/主题配额、DPP（θ 从 0.5 起调）、10–20% 探索槽，标注"探索"。新论文和新作者用贝叶斯分级曝光（内容先验 + Thompson，按后验下界逐级扩大受众），并设曝光下限。可见性过滤（撤稿、屏蔽、已看、授权）与排序分属不同阶段。
5. **双向匹配三层**：
   - ① 读者↔论文：受众适配 + 供给侧约束的重排；
   - ② 论文→读者反向推送：Percolator 按节点倒排与用户质心点积找读者，在"每用户日预算 + 每篇曝光下限"约束下分配（贪心；硬配额场景用最小费用流）；
   - ③ 研究者↔研究者：互惠分（调和平均）+ 容量与公平约束，**双方都选择加入才启用**，默认关闭。
6. **反馈与社交**：
   - 信号阶梯：停留 → 中性跳过 → 左右滑 → 点赞 → 收藏 → 1–5 星 → 评论/笔记 → 导出引用；
   - 所有反馈绑定 impression；撤销为追加事件。
   - 公开评分用 Wilson 下界，并设最少评分数；作者对自己论文的互动不计入。
   - 社会证明至少需要 k 个不同用户（k 由 05/06 给出初值）；协同类 why-this 理由同样要满足 k 匿名，私有派生的理由只对本人可见。
   - 评论默认私有；公开评论须实名锚定并经审核。
7. **冷启动**：兴趣树勾选 → 导入种子（ORCID 本人作品、Zotero、BibTeX、DOI、v1 preset）→ 10–20 张主动学习校准卡。

### 6.5 前端交互（→ 07 + demo）

1. **三件套**：今日分拣 Deck 作默认首页；双列瀑布流用于"收藏库/探索"；详情用底部 Sheet。纯抖音式纵向流只作实验入口。界面只保留完成"分拣 → 细读 → 收藏"所需的元素。
2. **手势映射 A**：→ 想读（喜欢）、← 不感兴趣、↑ 中性下一篇、↓ 撤回上一张、单击进详情、长按出原因菜单。Deck 上不绑定双击。
3. **判定与动效**（参数取自 ux 调研 §2.3/§2.9，demo 中提供调参面板供评审）：
   - 投影判定 proj = d + v·0.1s；横向阈值 0.35W，纵向 0.2H，逃逸速度 800 pt/s；
   - 跟手 1:1，旋转上限 ±12°；
   - 回弹 spring 500/36，次卡升位 600/49；
   - Reduce Motion 时全部改为 150 ms 淡入淡出。
4. **卡片 P0 字段 6 项**：标题、AI TL;DR（标注、可关，永不替代作者摘要）、venue·年份、评审状态、OA 状态四态、why-this。关键图只对 CC 许可论文展示。分拣卡不显示社交计数。
5. **等价操作**：每个手势都有按钮与键盘等价（满足 WCAG 2.2）；撤销免费不限次。
6. **技术**：v2.0 Web-first PWA；前端与推荐服务的**事件契约先行**（事件名与字段由 06 定义、07 引用、05 落表）。
