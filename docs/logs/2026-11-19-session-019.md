# Session 019 · 2026-11-19 · Scout：本地 AI 会议论文检索服务

> 执行者：Claude Opus 5.5（Pi），操作人 `yhyfhgs`。分支 `feat/scout-local-search`。

## 起因

`yhyfhgs` 要求在 Confluo 里做一个本地小服务：动态 venue 列表、按平台的鲁棒爬虫（开放审稿届次取审稿分与置信度，已结束届次取 oral、spotlight、highlight、poster）、论文元数据入库、摘要分片压缩、Google 最新开源嵌入模型的向量库、关键词 + BM25 + 同义模糊 + 向量 + 决策模型的多跳收敛检索、精简美观的前端，以 Docker 部署在本机，数据放在 data 盘；设计方案写好放进 vault inbox，不停下等确认。

## 调研结论（均为 2026-11-19 核实）

- Google 最新开源嵌入模型是 EmbeddingGemma 2（2026-10-06，Apache-2.0，`google/embeddinggemma-2`，最大 740M，文本路径 270M，768 维）。
- "jev 类 decision model" 对应 Gemini Decisions API 的 `gemini-decision-1`（2026-11-11）；Jev 是 TypeSafe AI 的同类 System One 模型。
- OpenReview 匿名 `/notes` 返回 403 ChallengeRequiredError，登录后限额 `500;w=3600`；ICLR 2027 审稿分已公开。会议官网 `/static`（virtual 站点 JSON）被 robots 禁止；CVPR、ICCV 的 AcceptedPapers 页只标 Highlight。
- IJCAI 的 robots 已撤销 9 月记录的 `Crawl-delay: 10`，并提供每篇论文的 `.json`；AAAI 的 OAI 端点在部分页稳定返回 500。

## 发现与处理

- `~/.zshenv` 里的 `CONFLUO_HOME` 仍指向改名前的 `~/Projects/ActionMesh AI/Confluo/.confluo`；Scout 改为在目录不存在时退回仓库 `.confluo/` 并警告，变量本身未改（不在任务范围内）。

- 容器内 PyTorch CPU 编码约每秒 4–6 篇，宿主机 MPS 约每秒 24 篇；首轮批量向量化用 `make embed-host`。

## 事故：在用库被宿主机访问写坏（02:14）

- 经过：库文件放在 virtiofs 绑定挂载上。容器写库期间，我在宿主机上用 `sqlite3` 只读查询了几次。宿主机连接关闭时把自己当作最后一个连接，做了 WAL 检查点并删除了 WAL，库文件头被清零，容器新开连接报 `file is not a database`。
- 恢复：停容器；从容器 02:11:46 的在线备份恢复（`integrity_check` 通过，73,535 篇）；按断点续爬；摘要指针按当前分片代重新对齐；越界向量为 0。
- 对策：在用库移入 Docker 卷 `scout-db`，宿主机碰不到；每 6 小时和停机时各备份一次到数据目录，保留 4 份；卷为空时启动自动恢复并对账；宿主机命令改用自己的副本 `scout-host.sqlite`；首轮批量编码改由宿主机只算向量的加速服务（`make embed-serve`）承担，宿主机不再接触库。
- 同期发现并修复：CVF、ECVA、IJCAI 适配器被停止时把断点存成"已完成"，导致摘要缺口（CVPR 2025 只有 333/2,871）；已改为保存真实位置，并重新排队补抓。
